I wanted Seafile running in its own VM, with my files on Unraid and HTTPS handled by the Nginx Proxy Manager instance I already use. That sounds pretty simple, but there are a few pieces to connect: the storage mount, database, document editor, and notification service all need to agree on where things live.

In this guide, we'll build that setup with Seafile Community Edition 13, Fedora Server, and Docker Compose. We'll also include SeaDoc for editing documents in the browser and Seafile's notification server for real-time library updates. Everything will be available through one address, such as `https://seafile.example.com`.

My deployment ran Seafile **13.0.25** and SeaDoc **2.0.9**. The examples follow the 13.x configuration and use its update tags. I've combined the services into one Compose file to make the walkthrough easier to follow. This is a customized version of the [official Seafile 13 Docker setup](https://manual.seafile.com/13.0/setup/setup_ce_by_docker/), with an existing reverse proxy and separate local and Unraid storage.

## What we're building

Nginx Proxy Manager, or NPM, stays on your existing server. It accepts the HTTPS connection and forwards requests to port **8080** on the Seafile VM. A small NGINX container inside that VM sends each request to the right service.

```text
Your browser or Seafile client
          |
          | HTTPS: seafile.example.com
          v
Existing Nginx Proxy Manager
          |
          | HTTP: 192.168.1.50:8080
          v
NGINX gateway in the Fedora VM
          |
          +-- Seafile: files, accounts, and web interface
          +-- SeaDoc: collaborative document editor
          +-- Notification server: real-time updates

VM local disk                     Unraid share, mounted in the VM
/srv/seafile                      /mnt/seafile
  Compose files                     Seafile files and configuration
  Live MariaDB database             SeaDoc persistent files
                                    Database and configuration backups
```

There are six containers: those three application services, MariaDB, Redis, and the NGINX gateway. Only the gateway publishes a port on the VM. The database and Redis stay on Docker's internal network.

## Before you start

This walkthrough assumes a **new, dedicated Fedora Server VM on Unraid**. It is a fresh installation guide, so don't paste these files over an existing Seafile deployment without reviewing its configuration first.

You'll need:

- An x86-64 Fedora Server VM. I used Fedora 44, with 4 GB of RAM and four virtual CPUs across two physical cores.
- A local virtual disk with room for Fedora, container images, and the growing database. I'd start around 50 GB or larger, depending on your library size.
- An Unraid user share named `seafile`, with enough space for your files and backups.
- An existing NPM instance that can reach the VM over your network.
- A domain you control, with its Seafile hostname pointing to NPM.
- A Fedora account with `sudo` access and basic familiarity with SSH.

Seafile lists two CPU cores and 2 GB of memory for CE, with additional resources needed for extra services. See its [system requirements](https://manual.seafile.com/13.0/setup/system_requirements/) when sizing a larger installation.

Use these examples consistently as you go:

| Setting | Example | What to use |
| --- | --- | --- |
| VM address | `192.168.1.50` | Your Fedora VM's LAN address |
| Public hostname | `seafile.example.com` | Your actual Seafile domain |
| Administrator | `you@example.com` | Your email address |
| VM hostname | `fedora-seafile` | This can stay as shown |
| Unraid mount tag | `seafile` | Must match the VM share setting |

Reserve the VM's address in your router or DHCP server so NPM's forwarding target doesn't change after a reboot.

Unless a step specifically says **Unraid**, **NPM**, or **your computer**, run its commands in the **Fedora VM over SSH**. We'll use `nano` to edit files. In nano, save with **Ctrl+O**, press **Enter**, then exit with **Ctrl+X**.

## 1. Prepare the VM in Unraid

Shut down the VM before changing its hardware settings. In Unraid's VM editor, set the CPU mode to **Host Passthrough** and assign at least two CPU cores. My setup uses two cores and their matching threads, giving Fedora four virtual CPUs.

This fixed an issue I ran into during installation: the VM's generic QEMU CPU model hid instructions needed by a bundled Python dependency. The login page loaded, but an API request returned an error about `X86_V2`. Host Passthrough exposed the real CPU features. The physical CPU still needs to support the instructions the software requires.

Add the Unraid share with these settings:

| Unraid VM setting | Value |
| --- | --- |
| Unraid Share Mode | `9p Mode` |
| Unraid Share | `User:seafile` |
| Unraid Source Path | `/mnt/user/seafile/` |
| Unraid Mount Tag | `seafile` |

Start the VM and reconnect with SSH. Set its hostname:

```bash
sudo hostnamectl set-hostname fedora-seafile
hostnamectl
```

The VM hostname is its Linux system name. Your public Seafile domain is a separate setting we'll configure later.

## 2. Understand `/srv` versus `/mnt`

Here's the storage split we're going to use:

| Path inside Fedora | Underlying storage | Purpose |
| --- | --- | --- |
| `/srv/seafile` | VM's local virtual disk | Compose project, environment file, proxy configuration, backup script |
| `/srv/seafile/mysql` | VM's local virtual disk | Live MariaDB database |
| `/mnt/seafile/seafile-data` | Unraid share | Seafile's stored file blocks, application configuration, and logs |
| `/mnt/seafile/seadoc-data` | Unraid share | SeaDoc's persistent directory, including logs |
| `/mnt/seafile/backups` | Unraid share | Nightly SQL dumps and configuration archives |

`/srv` is a conventional place for service-related data. `/mnt` is a conventional place to mount another filesystem. **The directory names don't move data onto a different disk.** Mounting the Unraid share at `/mnt/seafile` is what makes files written there land on Unraid.

I'm keeping MariaDB local because it does frequent small reads and writes and depends on reliable filesystem behavior. A local Linux filesystem is a more straightforward home for that workload than the VM's 9p share. We can still send database backups to Unraid every night.

Also, putting the Compose project in `/srv/seafile` doesn't relocate Docker itself. Docker's images, writable container layers, and runtime storage still use its local defaults, including `/var/lib/docker` and, depending on the installation, containerd's storage.

One other detail: Seafile manages files using its own storage format. You won't find a regular folder tree of your uploaded documents under `seafile-data`. Upload existing files through Seafile's web interface or client. Don't copy a collection of documents into that directory and expect them to appear in your libraries.

## 3. Mount the Unraid share inside Fedora

The 9p share is passed from Unraid to the VM through the virtual hardware. You don't enter an SMB server address or mount it using Unraid's IP. The name `seafile` below is the **mount tag** from the VM settings. Linux documents this transport in its [9p filesystem guide](https://docs.kernel.org/filesystems/9p.html).

Create the mount point and try the mount:

```bash
sudo mkdir -p /mnt/seafile
sudo mount -t 9p -o trans=virtio,version=9p2000.L,cache=none seafile /mnt/seafile
findmnt /mnt/seafile
```

You should see `/mnt/seafile` with filesystem type `9p` and source `seafile`. If that fails, stop here and check the Unraid mount tag before creating application folders.

Test that your normal Fedora user can write to the share:

```bash
touch /mnt/seafile/.write-test
rm /mnt/seafile/.write-test
```

If you get a permission error, check the Unraid share's ownership and permissions for the mapped VM user. Don't apply a recursive `chmod 777` to your NAS to work around it.

Make the mount persistent. Back up the existing file, then open it:

```bash
sudo cp -a /etc/fstab /etc/fstab.before-seafile
sudo nano /etc/fstab
```

Add this as **one new line**, keeping the existing entries:

```text
seafile /mnt/seafile 9p trans=virtio,version=9p2000.L,cache=none,rw,nofail,x-systemd.mount-timeout=30s 0 0
```

Check the file and reload systemd:

```bash
sudo findmnt --verify
sudo systemctl daemon-reload
sudo systemctl start mnt-seafile.mount
findmnt /mnt/seafile
```

`nofail` lets Fedora finish booting if the share is unavailable. Later, we'll tell Docker and Seafile to require the mount. That way, you can still reach the VM to fix storage without letting the application write into an empty local mount point.

## 4. Install Docker and create the folders

Install Docker Engine and its Compose plugin using the [official Fedora instructions](https://docs.docker.com/engine/install/fedora/):

```bash
sudo dnf install -y dnf-plugins-core nano curl openssl
sudo dnf config-manager addrepo --from-repofile https://download.docker.com/linux/fedora/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker version
sudo docker compose version
```

Use `docker compose` with a space. We'll run it with `sudo`, so you don't need to change your user's Docker group membership for this guide. If Docker reports a package conflict on a VM you've used before, review the conflict guidance on that Fedora installation page.

Check your user's numeric IDs:

```bash
id -u
id -g
```

The following commands assume both are **1000**. If yours differ, substitute your IDs in the ownership commands. We want the **project directory** owned by `1000:1000`; each container can still manage the ownership it needs for its own data.

```bash
sudo install -d -o 1000 -g 1000 -m 0750 /srv/seafile
sudo install -d -m 0750 /srv/seafile/mysql
```

Confirm the share is mounted, then create its application directories:

```bash
mountpoint /mnt/seafile
```

Only continue when that reports that `/mnt/seafile` is a mount point:

```bash
sudo mkdir -p /mnt/seafile/seafile-data/seafile/logs
sudo mkdir -p /mnt/seafile/seadoc-data
sudo install -d -o 1000 -g 1000 -m 0700 /mnt/seafile/backups
cd /srv/seafile
```

Don't recursively change `/srv/seafile` to `1000:1000` after the database has started. MariaDB will set its data directory's ownership for the user inside its container. For the same reason, we aren't adding `user: "1000:1000"` to every service.

## 5. Create the environment file

The `.env` file holds the settings Compose will insert into the container configuration. We'll generate separate random passwords automatically, then edit the domain, IP, email, and time zone.

Run this whole block from `/srv/seafile`. It is for the **first setup only**, since running it again would overwrite your saved settings and passwords.

```bash
umask 077
cat > .env << EOF
COMPOSE_PROJECT_NAME=seafile

SEAFILE_BIND_IP=192.168.1.50
SEAFILE_SERVER_HOSTNAME=seafile.example.com
SEAFILE_SERVER_PROTOCOL=https
TIME_ZONE=America/Los_Angeles

SEAFILE_IMAGE=seafileltd/seafile-mc:13.0-latest
SEAFILE_DB_IMAGE=mariadb:10.11
SEAFILE_REDIS_IMAGE=redis:7.4-alpine
SEADOC_IMAGE=seafileltd/sdoc-server:2.0-latest
NOTIFICATION_SERVER_IMAGE=seafileltd/notification-server:13.0-latest
GATEWAY_IMAGE=nginx:stable-alpine

SEAFILE_VOLUME=/mnt/seafile/seafile-data
SEADOC_VOLUME=/mnt/seafile/seadoc-data
SEAFILE_MYSQL_VOLUME=/srv/seafile/mysql

JWT_PRIVATE_KEY=$(openssl rand -hex 32)
SEAFILE_MYSQL_DB_PASSWORD=$(openssl rand -hex 24)
INIT_SEAFILE_MYSQL_ROOT_PASSWORD=$(openssl rand -hex 24)
REDIS_PASSWORD=$(openssl rand -hex 24)
INIT_SEAFILE_ADMIN_EMAIL=you@example.com
INIT_SEAFILE_ADMIN_PASSWORD=$(openssl rand -hex 24)

ENABLE_SEADOC=true
ENABLE_NOTIFICATION_SERVER=true
EOF
nano .env
```

Replace `SEAFILE_BIND_IP`, `SEAFILE_SERVER_HOSTNAME`, and `INIT_SEAFILE_ADMIN_EMAIL` with your values. Set your time zone too. The hostname must contain just the domain, without `https://` or a trailing slash.

Copy `INIT_SEAFILE_ADMIN_PASSWORD` into your password manager before closing the file. Leave `SEAFILE_SERVER_PROTOCOL=https`: that's the address your browser will use, even though NPM connects to the VM over HTTP.

The `JWT_PRIVATE_KEY` is a shared secret used by Seafile and its add-ons to authenticate requests between them. Our Compose file passes the same value to all three services. You don't need to create a PEM file or generate separate keys for each container.

The `INIT_` administrator settings initialize a new installation. Editing them later doesn't reset an existing account's password. Keep `.env` private and out of Git repositories.

## 6. Add the Compose file

Create the file:

```bash
nano compose.yaml
```

Paste the complete configuration below. It is long because it includes all six services, health checks, and explicit storage mounts. You shouldn't need to edit it if you used the paths above and customized `.env`.

```yaml
services:
  db:
    image: ${SEAFILE_DB_IMAGE}
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${INIT_SEAFILE_MYSQL_ROOT_PASSWORD:?Set in .env}
      MYSQL_LOG_CONSOLE: "true"
      MARIADB_AUTO_UPGRADE: "1"
    volumes:
      - type: bind
        source: ${SEAFILE_MYSQL_VOLUME}
        target: /var/lib/mysql
        bind:
          create_host_path: false
    healthcheck:
      test: ["CMD", "/usr/local/bin/healthcheck.sh", "--connect", "--mariadbupgrade", "--innodb_initialized"]
      interval: 20s
      timeout: 5s
      retries: 10
      start_period: 30s
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  redis:
    image: ${SEAFILE_REDIS_IMAGE}
    restart: unless-stopped
    environment:
      REDIS_PASSWORD: ${REDIS_PASSWORD:?Set in .env}
    command:
      - /bin/sh
      - -c
      - exec redis-server --requirepass "$$REDIS_PASSWORD" --save "" --appendonly no
    healthcheck:
      test: ["CMD-SHELL", "REDISCLI_AUTH=\"$$REDIS_PASSWORD\" redis-cli ping | grep -q PONG"]
      interval: 20s
      timeout: 5s
      retries: 5
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  seafile:
    image: ${SEAFILE_IMAGE}
    restart: unless-stopped
    volumes:
      - type: bind
        source: ${SEAFILE_VOLUME}
        target: /shared
        bind:
          create_host_path: false
    environment:
      SEAFILE_MYSQL_DB_HOST: db
      SEAFILE_MYSQL_DB_PORT: "3306"
      SEAFILE_MYSQL_DB_USER: seafile
      SEAFILE_MYSQL_DB_PASSWORD: ${SEAFILE_MYSQL_DB_PASSWORD:?Set in .env}
      INIT_SEAFILE_MYSQL_ROOT_PASSWORD: ${INIT_SEAFILE_MYSQL_ROOT_PASSWORD:?Set in .env}
      SEAFILE_MYSQL_DB_CCNET_DB_NAME: ccnet_db
      SEAFILE_MYSQL_DB_SEAFILE_DB_NAME: seafile_db
      SEAFILE_MYSQL_DB_SEAHUB_DB_NAME: seahub_db
      INIT_SEAFILE_ADMIN_EMAIL: ${INIT_SEAFILE_ADMIN_EMAIL:?Set in .env}
      INIT_SEAFILE_ADMIN_PASSWORD: ${INIT_SEAFILE_ADMIN_PASSWORD:?Set in .env}
      SEAFILE_SERVER_HOSTNAME: ${SEAFILE_SERVER_HOSTNAME:?Set in .env}
      SEAFILE_SERVER_PROTOCOL: ${SEAFILE_SERVER_PROTOCOL}
      TIME_ZONE: ${TIME_ZONE}
      JWT_PRIVATE_KEY: ${JWT_PRIVATE_KEY:?Set in .env}
      NON_ROOT: "false"
      CACHE_PROVIDER: redis
      REDIS_HOST: redis
      REDIS_PORT: "6379"
      REDIS_PASSWORD: ${REDIS_PASSWORD:?Set in .env}
      ENABLE_SEADOC: ${ENABLE_SEADOC}
      SEADOC_SERVER_URL: ${SEAFILE_SERVER_PROTOCOL}://${SEAFILE_SERVER_HOSTNAME}/sdoc-server
      ENABLE_NOTIFICATION_SERVER: ${ENABLE_NOTIFICATION_SERVER}
      INNER_NOTIFICATION_SERVER_URL: http://notification-server:8083
      NOTIFICATION_SERVER_URL: ${SEAFILE_SERVER_PROTOCOL}://${SEAFILE_SERVER_HOSTNAME}/notification
      ENABLE_SEAFILE_AI: "false"
      ENABLE_FACE_RECOGNITION: "false"
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS -H \"Host: $$SEAFILE_SERVER_HOSTNAME\" http://localhost:80/api2/server-info/ > /dev/null"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 180s
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  seadoc:
    image: ${SEADOC_IMAGE}
    restart: unless-stopped
    volumes:
      - type: bind
        source: ${SEADOC_VOLUME}
        target: /shared
        bind:
          create_host_path: false
    environment:
      DB_HOST: db
      DB_PORT: "3306"
      DB_USER: seafile
      DB_PASSWORD: ${SEAFILE_MYSQL_DB_PASSWORD:?Set in .env}
      DB_NAME: seahub_db
      TIME_ZONE: ${TIME_ZONE}
      JWT_PRIVATE_KEY: ${JWT_PRIVATE_KEY:?Set in .env}
      NON_ROOT: "false"
      SEAHUB_SERVICE_URL: http://seafile
    depends_on:
      db:
        condition: service_healthy
      seafile:
        condition: service_healthy
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  notification-server:
    image: ${NOTIFICATION_SERVER_IMAGE}
    restart: unless-stopped
    volumes:
      - type: bind
        source: ${SEAFILE_VOLUME}/seafile/logs
        target: /shared/seafile/logs
        bind:
          create_host_path: false
    environment:
      SEAFILE_MYSQL_DB_HOST: db
      SEAFILE_MYSQL_DB_PORT: "3306"
      SEAFILE_MYSQL_DB_USER: seafile
      SEAFILE_MYSQL_DB_PASSWORD: ${SEAFILE_MYSQL_DB_PASSWORD:?Set in .env}
      SEAFILE_MYSQL_DB_CCNET_DB_NAME: ccnet_db
      SEAFILE_MYSQL_DB_SEAFILE_DB_NAME: seafile_db
      JWT_PRIVATE_KEY: ${JWT_PRIVATE_KEY:?Set in .env}
    depends_on:
      db:
        condition: service_healthy
      seafile:
        condition: service_healthy
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  gateway:
    image: ${GATEWAY_IMAGE}
    restart: unless-stopped
    ports:
      - "${SEAFILE_BIND_IP:?Set in .env}:8080:80"
    volumes:
      - type: bind
        source: /srv/seafile/gateway.conf
        target: /etc/nginx/conf.d/default.conf
        read_only: true
        bind:
          create_host_path: false
    depends_on:
      seafile:
        condition: service_healthy
      seadoc:
        condition: service_started
      notification-server:
        condition: service_started
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1/api2/server-info/"]
      interval: 30s
      timeout: 10s
      retries: 3
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"
```

Compose creates a private network for this project automatically. On that network, the service name `db` resolves to MariaDB, `seafile` resolves to Seafile, and so on. These names aren't public DNS records you need to create.

The `source` of each bind mount is a path on Fedora. The `target` is where that directory appears inside the container. `create_host_path: false` makes a missing source directory an error instead of silently creating one. We'll add a separate mount check too, because an existing directory alone doesn't prove Unraid is mounted.

The logging settings cap Docker's own container logs. Application log files written into the shared data directories have their own rotation behavior and still need disk space.

## 7. Add the internal NGINX gateway

Create the gateway configuration:

```bash
nano gateway.conf
```

Paste this file exactly as shown. It uses the incoming domain automatically, so there is no example hostname to replace here.

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

server {
    listen 80 default_server;
    server_name _;
    server_tokens off;

    client_max_body_size 0;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_buffering off;
    proxy_request_buffering off;

    location /sdoc-server/ {
        proxy_pass http://seadoc:80/;
    }

    location /socket.io {
        proxy_pass http://seadoc:80;
    }

    location = /notification {
        proxy_pass http://notification-server:8083/;
    }

    location /notification/ {
        proxy_pass http://notification-server:8083/;
    }

    location / {
        proxy_pass http://seafile:80;
    }
}
```

The gateway keeps the NPM side pretty simple: one domain and one forwarding port. Seafile gets the normal application requests, while the other locations handle SeaDoc and notifications.

Keep the trailing slashes as shown. For example, `/notification/ping` needs to arrive at the notification container as `/ping`. The WebSocket headers allow the persistent connections used by the add-ons. This follows the routing described in Seafile's [external reverse proxy guide](https://manual.seafile.com/13.0/setup/use_other_reverse_proxy/) and [NGINX's WebSocket documentation](https://nginx.org/en/docs/http/websocket.html).

We explicitly forward `X-Forwarded-Proto https` because NPM handles the encrypted browser connection. Port 8080 is an HTTP backend for your trusted network; don't forward it directly from your internet router.

Check the Compose configuration without printing its resolved passwords:

```bash
chmod 600 .env
chmod 640 compose.yaml gateway.conf
sudo docker compose config --quiet
sudo docker compose pull
```

No output from `config --quiet` means validation passed. Image downloads can take a few minutes.

## 8. Make startup wait for Unraid

This step matters. If Docker starts before the share mounts, container restart policies can bring the application back before your storage is ready.

Since this is a **dedicated Seafile VM**, we'll make the Docker daemon itself depend on the share. This affects every Docker container on the VM. On a shared Docker host, you'd need a startup arrangement that accounts for its other applications too.

Create a Docker service override:

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo nano /etc/systemd/system/docker.service.d/seafile-storage.conf
```

```ini
[Unit]
RequiresMountsFor=/mnt/seafile
BindsTo=mnt-seafile.mount
After=mnt-seafile.mount
```

Now create a systemd service for the Compose project:

```bash
sudo nano /etc/systemd/system/seafile.service
```

```ini
[Unit]
Description=Seafile Docker Compose stack
Requires=docker.service
Wants=network-online.target
After=docker.service network-online.target mnt-seafile.mount
RequiresMountsFor=/mnt/seafile /srv/seafile
BindsTo=mnt-seafile.mount
PartOf=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/srv/seafile
ExecStartPre=/usr/bin/mountpoint -q /mnt/seafile
ExecStart=/usr/bin/docker compose up -d --wait --wait-timeout 360
ExecStop=/usr/bin/docker compose down --timeout 60
TimeoutStartSec=600
TimeoutStopSec=180

[Install]
WantedBy=multi-user.target
```

This tells systemd where the project lives, checks the mount, and starts the containers. The mount dependency controls ordering, while `BindsTo` stops the dependent service if systemd sees the mount go away.

Start everything:

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
sudo systemctl enable --now seafile.service
sudo docker compose ps
```

The first start creates the databases, initial administrator, and application configuration. Give it a few minutes. The database, Redis, Seafile, and gateway should become healthy; SeaDoc and the notification server should be running. We'll check the add-ons through HTTPS shortly.

If startup fails, read the logs before changing anything:

```bash
sudo journalctl -u seafile.service -n 80 --no-pager
sudo docker compose logs --tail=100 db seafile
```

For a slow first initialization, inspect the logs and retry with `sudo systemctl restart seafile.service` once you've resolved the issue. You don't need to delete the database and start over.

## 9. Point Nginx Proxy Manager at the VM

In your **existing NPM interface**, create a Proxy Host with these settings:

| NPM field | Value |
| --- | --- |
| Domain Names | Your domain, such as `seafile.example.com` |
| Scheme | `http` |
| Forward Hostname / IP | Your Fedora VM, such as `192.168.1.50` |
| Forward Port | `8080` |
| Websockets Support | Enabled |
| Cache Assets | Disabled |

In the **SSL** tab, select or request a valid certificate for the domain and enable **Force SSL**. Your DNS and certificate-validation method need to work with your existing NPM setup.

In the **Advanced** tab, add:

```nginx
client_max_body_size 0;
proxy_request_buffering off;
proxy_buffering off;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
```

These settings remove NGINX's request-body size cap and give transfers longer timeouts. Other services in front of NPM, such as a CDN, may still impose their own limits.

You don't need extra NPM Custom Locations with this configuration. The gateway in the VM already handles `/sdoc-server/`, `/socket.io`, and `/notification`.

Save the proxy host and open your HTTPS domain. Log in with the email and generated administrator password from `.env`.

## 10. Check files, SeaDoc, and notifications

Before adding your real files, make a temporary library and upload a small document or image. Download it again and check the contents. Then try a larger file representative of what you normally store.

For my deployment, I also verified a 1 MiB upload and download through the public HTTPS endpoint and compared the downloaded bytes. That checks the complete proxy path, but it isn't a large-file performance benchmark.

You can check the basic endpoints from **your computer or the VM**. Replace the example domain in these commands:

```bash
curl -fsS https://seafile.example.com/api2/ping/
curl -fsS https://seafile.example.com/api2/server-info/
curl -fsS https://seafile.example.com/sdoc-server/
curl -fsS https://seafile.example.com/notification/ping
```

Expect `pong` from Seafile's ping, version information from `server-info`, a SeaDoc welcome response, and a response containing `"ret":"pong"` from the notification server. Don't add `-k` to hide certificate problems; fix the certificate or hostname if HTTPS validation fails.

### SeaDoc: documents in the browser

In a library, use the **New** menu to create a SeaDoc document. Enter a few lines, wait for saving to finish, close it, then reopen it. Your text should still be there. If you plan to collaborate, share a test document with a second account and try editing from two browser sessions.

SeaDoc edits Seafile's `.sdoc` documents. Its persistent directory includes logs, while document contents live in Seafile and its operation log uses the existing `seahub_db` database. It doesn't need a separate `sdoc_db` for this version. The [Seafile 13 SeaDoc instructions](https://manual.seafile.com/13.0/extension/setup_seadoc/) explain that integration.

This is useful for notes and shared documentation. Opening an uploaded Word document is a separate feature: SeaDoc doesn't provide the browser viewer for `.docx` files. With the setup in this guide, you can still store, sync, and download those files, but Seafile may display **"Online view is not applicable to this file format"** when you try to preview one.

#### Optional: OnlyOffice or Collabora for Office files

Seafile supports two additional office suites for viewing and editing documents in the browser:

- **[OnlyOffice Docs](https://manual.seafile.com/13.0/extension/only_office/)** provides editors for Word, Excel, and PowerPoint formats, including `.docx`, `.xlsx`, and `.pptx`. The component you want for this integration is **Document Server**.
- **[Collabora Online](https://manual.seafile.com/13.0/extension/collabora_online/)** is a LibreOffice-based alternative that supports Microsoft Office and OpenDocument formats. Its free [CODE edition](https://www.collaboraonline.com/code/) is intended for development, home use, and small teams; the supported production edition is a separate offering.

Either can work alongside SeaDoc. Both require an additional office service, a connection to Seafile, and reverse proxy configuration. Enabling SeaDoc alone doesn't enable either integration.

Plan extra resources before adding one. For example, [OnlyOffice's Docker requirements](https://helpcenter.onlyoffice.com/docs/installation/docs-community-install-docker.aspx) list 4 GB of RAM and 40 GB of free disk space for its deployment. Don't treat the 4 GB Seafile VM used above as a sizing recommendation for the combined stack. Document complexity and the number of simultaneous editors matter, so test opening, editing, saving, and reopening a few of your own files.

These are optional next steps; the Compose file in this guide installs Seafile, SeaDoc, and notifications. Follow the linked version-specific integration instructions when you're ready to add an office suite.

### Notifications: live connections, separate from email

The [notification server](https://manual.seafile.com/13.0/extension/notification-server/) uses WebSockets to notify supported clients about changes to libraries. We enable it in Seafile, run its container, and route its public URL through the gateway.

An HTTP ping confirms the route works, but doesn't prove WebSockets work. Open your browser's developer tools, select **Network**, filter for **WS**, and reload an open library or SeaDoc document. Look for connections to `/notification` and, while editing a SeaDoc document, `/socket.io`. A successful WebSocket upgrade has status **101**.

This service doesn't configure invitation emails, password-reset emails, or an SMTP server. Those are separate settings under the manual's **Configuration → Email Sending** section.

## 11. Send database and configuration backups to Unraid

Our uploaded files already live on Unraid, but the live database is on the VM. We'll create a nightly SQL dump of all three Seafile databases and archive the configuration alongside it.

**This job isn't a second copy of your uploaded files.** It places database and configuration backups on the same Unraid system holding the file data. For protection from losing that system, also replicate the Seafile data directories and these backups to another device or location.

Create the backup script in the Fedora VM:

```bash
cd /srv/seafile
nano backup.sh
```

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 077

cd /srv/seafile
mountpoint -q /mnt/seafile

backup_root=/mnt/seafile/backups
stamp=$(date -u +%Y%m%dT%H%M%SZ)
work_dir=$(mktemp -d "$backup_root/.incomplete.$stamp.XXXXXX")

# The root password is read inside the database container.
docker compose exec -T db sh -c '
  MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mariadb-dump --user=root \
    --single-transaction --quick --routines --events --triggers --hex-blob \
    --databases ccnet_db seafile_db seahub_db
' | gzip > "$work_dir/databases.sql.gz"

config_paths=(
  srv/seafile/.env
  srv/seafile/compose.yaml
  srv/seafile/gateway.conf
  srv/seafile/backup.sh
  etc/fstab
  etc/systemd/system/docker.service.d/seafile-storage.conf
  etc/systemd/system/seafile.service
  etc/systemd/system/seafile-backup.service
  etc/systemd/system/seafile-backup.timer
)

for directory in \
  mnt/seafile/seafile-data/seafile/conf \
  mnt/seafile/seafile-data/nginx; do
  if [[ -d "/$directory" ]]; then
    config_paths+=("$directory")
  fi
done

tar -C / -czf "$work_dir/config.tar.gz" "${config_paths[@]}"
gzip -t "$work_dir/databases.sql.gz" "$work_dir/config.tar.gz"
chmod 600 "$work_dir/databases.sql.gz" "$work_dir/config.tar.gz"
chown -R 1000:1000 "$work_dir"
mv "$work_dir" "$backup_root/$stamp"
printf 'Backup completed: %s/%s\n' "$backup_root" "$stamp"
```

If your user IDs aren't `1000:1000`, change that one ownership line. The script uses a temporary directory and only renames it after success. A folder starting with `.incomplete` means that run didn't finish; check the journal before relying on it.

The configuration archive includes `.env`, so treat backups as private too. This script doesn't delete old backups automatically. Check how much space they use and decide on retention once you know your database's size.

Make it executable:

```bash
chmod 750 backup.sh
```

### Schedule the backup

Create a service:

```bash
sudo nano /etc/systemd/system/seafile-backup.service
```

```ini
[Unit]
Description=Back up Seafile databases and configuration to Unraid
Requires=docker.service
After=docker.service seafile.service
RequiresMountsFor=/mnt/seafile

[Service]
Type=oneshot
WorkingDirectory=/srv/seafile
ExecStart=/srv/seafile/backup.sh
UMask=0077
TimeoutStartSec=1h
```

Create its timer:

```bash
sudo nano /etc/systemd/system/seafile-backup.timer
```

```ini
[Unit]
Description=Nightly Seafile database backup

[Timer]
OnCalendar=*-*-* 03:30:00
Persistent=true
RandomizedDelaySec=5m
Unit=seafile-backup.service

[Install]
WantedBy=timers.target
```

This runs around 3:30 a.m. in the **VM's system time zone**, with up to five minutes of delay. Check `timedatectl` if that differs from your expected time. The container's `.env` time-zone setting doesn't change Fedora's system clock settings.

Enable the schedule and run a backup now:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now seafile-backup.timer
sudo systemctl start seafile-backup.service
sudo journalctl -u seafile-backup.service -n 30 --no-pager
systemctl list-timers seafile-backup.timer
ls -lh /mnt/seafile/backups
```

You should see a completed timestamped directory containing `databases.sql.gz` and `config.tar.gz`. Run the backup before major maintenance too:

```bash
sudo systemctl start seafile-backup.service
```

### What you need for a restore

A usable restore needs the **database dumps, Seafile's stored file data, and configuration**, including the shared secrets. Keeping only the SQL file or copying only `/srv/seafile` isn't enough.

When making a second copy of the files, run the database backup first and then back up the file data, following Seafile's [backup and recovery guidance](https://manual.seafile.com/13.0/administration/backup_recovery/). For a controlled restore test, use an isolated VM and keep client writes stopped while capturing a matching database and file-data backup.

The broad recovery order is to restore the data directories and configuration, start MariaDB, import all three SQL databases, and then start the application services. Test that on an isolated instance before depending on it. Copying MariaDB's live `/srv/seafile/mysql` directory while it is running is not a substitute for the SQL dump in this guide.

## 12. Reboot and check the complete setup

Once file uploads, document editing, and the first backup work, reboot the VM:

```bash
sudo reboot
```

Reconnect with SSH and check:

```bash
findmnt /mnt/seafile
systemctl status seafile.service --no-pager
cd /srv/seafile
sudo docker compose ps
systemctl list-timers seafile-backup.timer
```

For this type of systemd service, `active (exited)` is normal. The containers keep running after Compose finishes its startup command. Check their status with `docker compose ps` and open your HTTPS domain again.

Reopen your test document and download a test file. That confirms the application came back with its existing data after a reboot.

```

```

The `13.0-latest` tag follows Seafile's 13.0 series; it doesn't move you to the next major version. SeaDoc and the supporting containers have their own tags. ```

File uploads go to Unraid, but the local database and container images still consume space inside the VM.

## A few problems worth checking first

| Symptom | First thing to check |
| --- | --- |
| `mount` can't find the 9p share | The Unraid VM mount tag must be `seafile`, and the share must be attached to this VM. |
| Docker won't start after a reboot | Run `findmnt /mnt/seafile` and `journalctl -u mnt-seafile.mount`. The storage dependency may be doing its job. |
| NPM shows a 502 error | Confirm the VM's reserved IP, port 8080, and `docker compose ps`. NPM needs a network route to that address. |
| Login page loads but requests return 500 | Read Seafile's logs. If they mention missing `X86_V2` CPU support, check the VM CPU mode. |
| SeaDoc opens but won't connect or save | Check `/sdoc-server/`, WebSocket support, the shared JWT, and the `seadoc` logs. |
| Notification ping works but live updates don't | Check the `/notification` WebSocket connection for status 101. |
| Large uploads fail with 413 or time out | Check the body-size and timeout settings in both NPM and the gateway, plus any upstream proxy limits. |
| A bind mount reports permission denied | Check the specific directory's ownership and any SELinux denials before changing permissions. |

My Fedora deployment kept SELinux enforcing. Don't disable it as a general installation step, and don't add `:Z` relabeling to the 9p mounts without understanding whether that filesystem supports the labels your Docker configuration needs.

## Where the advanced add-ons fit

The manual separates **Advanced topics** from **Extensions**. For this setup, the advanced pieces are using an existing reverse proxy and controlling startup around mounted storage. SeaDoc and the notification server are the extensions we've enabled and connected.

If you're comparing this guide with the upstream files, the official deployment separates services into `seafile-server.yml`, `seadoc.yml`, and `notification-server.yml`, selected through `COMPOSE_FILE`. Its usual proxy configuration includes Caddy. Our single `compose.yaml` contains those application services and the NGINX gateway, with NPM handling the public certificate.

The [Extensions section](https://manual.seafile.com/13.0/extension/setup_seadoc/) also links to OnlyOffice, Collabora, WebDAV, and other integrations. Add those when you have a use for them and check the version and edition requirements. SeaDoc and notifications are already enough to get file storage, shared documents, and live updates working through the same domain.

At this point, you can create your real libraries and connect a Seafile client using your HTTPS address. Start with a small library, confirm it syncs as expected, and then bring over the rest of your files.
