Dashboards are one of my favorite parts of running a home server. They don't run the services, but having every service, a few handy widgets, and the stuff you check every day on one page is the part I like.

I've gone through plenty of them. Homepage, Heimdall (a longtime favorite), and most recently Homarr, which has a ton of features and integrates really well with the \*arr apps. The one I switched to, and the one I open more than any other, is [Glance](https://github.com/glanceapp/glance). It's beautiful, and the whole thing is configured with YAML. It gives you a quick *glance* at your entire home server. Sorry, I had to.

The video was published in March 2025. The written installation and every config example below have been updated for [Glance v0.8.8](https://github.com/glanceapp/glance/releases/tag/v0.8.8), released November 7, 2026, and checked against the current docs. v0.8.8 is a fix release and includes security fixes, so update an existing install. The config examples are the same. A few things changed in between: the include syntax, a built-in theme picker, optional login, and Pi-hole v6 support. My hands-on impressions come from the recorded walkthrough, and I've called out the changes where they matter.

## What Glance Is

Glance is an [AGPL-3.0](https://github.com/glanceapp/glance/blob/main/LICENSE) dashboard and feed reader written in Go. It ships as a single binary for Linux, Windows, and macOS, plus an official `glanceapp/glance` Docker image, and serves its web interface on port `8080` by default.

Everything is organized the same way:

- **Pages** show up as tabs in the navigation bar. The first page you define is the home page.
- **Columns** live inside a page. Each page can have up to three, either `small` (a fixed 300px sidebar) or `full` (takes the remaining width), and you need one or two `full` columns.
- **Widgets** go inside columns: RSS, YouTube, Hacker News, Reddit, weather, markets, search, service monitoring, DNS stats, GitHub releases, Docker containers, bookmarks, and a `custom-api` widget for pulling JSON from just about anything, among others.

Homarr has more features, at least for now. What Glance has is done really well, it's mobile friendly, and there are plenty of color schemes to pick from. If you want to read through everything before installing, the [configuration docs](https://github.com/glanceapp/glance/blob/main/docs/configuration.md) are one long Markdown file with every widget and property.

## Install Glance with Docker Compose

Docker Compose with the official template is the recommended method, and it's what I demoed in the video on another machine I already had Docker running on.

The [docker-compose-template](https://github.com/glanceapp/docker-compose-template) repository gives you a ready-to-edit project directory. Create it with the command from the Glance README:

```bash
mkdir glance && cd glance && curl -sL https://github.com/glanceapp/docker-compose-template/archive/refs/heads/main.tar.gz | tar -xzf - --strip-components 2
```

That leaves you with this layout:

| Path | What it's for |
|---|---|
| `docker-compose.yml` | The container, port, and volume mounts |
| `config/glance.yml` | Main config: server settings, theme, and the list of pages |
| `config/home.yml` | The default Home page, included from `glance.yml` |
| `assets/user.css` | An empty custom stylesheet, served by Glance under `/assets/` |
| `.env` | Variables you can reference anywhere in the config as `${NAME}` |

The `assets` folder is also where you can drop your own icons and images.

The template's compose file is below, with one change. I pinned the image to the current release instead of the floating default tag, so an update only happens when you decide to do one.

```yaml
services:
  glance:
    container_name: glance
    image: glanceapp/glance:v0.8.8
    restart: unless-stopped
    volumes:
      - ./config:/app/config
      - ./assets:/app/assets
      - /etc/localtime:/etc/localtime:ro
      # Optionally, also mount docker socket if you want to use the docker containers widget
      # - /var/run/docker.sock:/var/run/docker.sock:ro
    ports:
      - 8080:8080
    env_file: .env
```

The `/etc/localtime` mount lets the container use the host's timezone. Leave the Docker socket line commented out unless you want the Docker containers widget, since it gives Glance access to your Docker API.

The template's `.env` ships with a sample `MY_SECRET_TOKEN=123456` line. Delete it, and add your own values once you start configuring widgets that need them.

In the video I started it in the foreground first, so I could watch the logs and see it pull the image and start the server on port 8080:

```bash
docker compose up
```

Once you know it works, press Ctrl+C and run it in the background instead:

```bash
docker compose up -d
docker compose logs
```

Then open `http://YOUR_SERVER_IP:8080`. That's it, Glance running in Docker. Easy peasy.

<Warning>
Glance has no login by default. Anyone who can reach port 8080 can see your dashboard, including every internal service URL you put in it. Keep it on your LAN or behind a VPN, or turn on authentication (covered near the end). If you want remote access, my [NetBird and Pocket ID guide](/self-host-netbird-pocketid) is a good way to do it.
</Warning>

### Other Ways to Install It

The README also covers a manual compose setup with a single `glance.yml`, and precompiled binaries for Linux, Windows, and macOS. The binary looks for `glance.yml` in its own directory unless you pass `--config /path/to/glance.yml`. Third-party options include a NixOS package, Coolify, and the Proxmox VE helper script I use.

### The Proxmox Helper Script

My own instance came from the [community-scripts Glance script](https://community-scripts.org/scripts/glance), which you run from the Proxmox host's shell:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/glance.sh)"
```

This is a community project, not something the Glance developer maintains, so this is what the [install script](https://github.com/community-scripts/ProxmoxVE/blob/main/install/glance-install.sh) does. It creates an unprivileged LXC with Debian 13 or Alpine 3.24 (you choose), downloads the official prebuilt Glance binary from the GitHub releases into `/opt/glance`, writes a small starter config, and sets up a systemd service on Debian or an OpenRC service on Alpine. No extra services are bundled. Glance is then on port 8080 at the container's IP.

One thing changed since my video. Back then the config lived at `/opt/glance/glance.yml`, which is the file I opened with nano. New installs now keep it at `/opt/glance_data/glance.yml`, and the script's update routine moves older installs over to that location. After editing it, you don't need to restart anything. More on that in a minute.

## How the Config Is Laid Out

Opening the template's `config/glance.yml` in the video, I noticed the structure was slightly different from my single-file setup. It has a `server` section with the assets path, a `theme` section pointing at the custom CSS file, and a `pages` list that pulls in `home.yml`:

```yaml
server:
  assets-path: /app/assets

theme:
  # Note: assets are cached by the browser, changes to the CSS file
  # will not be reflected until the browser cache is cleared (Ctrl+F5)
  custom-css-file: /assets/user.css

pages:
  # It's not necessary to create a new file for each page and include it, you can simply
  # put its contents here, though multiple pages are easier to manage when separated
  - $include: home.yml
```

The `$include` syntax is newer than my video. Includes used to be written as `!include:`, but [v0.8.0](https://github.com/glanceapp/glance/releases/tag/v0.8.0) switched to `$include` because the old form wasn't valid YAML. Included files can also include other files now, so you can split things down to one file per page, column, or even widget.

Two rules save a lot of head scratching:

- An included page file starts at the top level with `- name: ...`. Don't put another `pages:` key inside it, or you'll get a `cannot unmarshal !!map into []glance.page` error.
- `${NAME}` pulls values from environment variables, which in this template means the `.env` file. That's where tokens and passwords should go instead of the YAML itself.

## Rebuild My Startpage

I didn't write my config from scratch. I took the [Startpage from the preconfigured pages](https://github.com/glanceapp/glance/blob/main/docs/preconfigured-pages.md#startpage), added the sidebar, and edited the heck out of it. A trimmed version of the page from the video, updated for current Glance, is below. Save it as `config/startpage.yml`:

```yaml
- name: Startpage
  width: slim
  hide-desktop-navigation: false
  center-vertically: true
  columns:
    - size: small
      widgets:
        - type: dns-stats
          service: pihole-v6
          url: http://192.168.1.53
          password: ${PIHOLE_PASSWORD}

        - type: custom-api
          title: Immich stats
          cache: 1d
          url: ${IMMICH_URL}/api/server/statistics
          headers:
            x-api-key: ${IMMICH_API_KEY}
            Accept: application/json
          template: |
            <div class="flex justify-between text-center">
              <div>
                  <div class="color-highlight size-h3">{{ .JSON.Int "photos" | formatNumber }}</div>
                  <div class="size-h6">PHOTOS</div>
              </div>
              <div>
                  <div class="color-highlight size-h3">{{ .JSON.Int "videos" | formatNumber }}</div>
                  <div class="size-h6">VIDEOS</div>
              </div>
              <div>
                  <div class="color-highlight size-h3">{{ div (.JSON.Int "usage" | toFloat) 1073741824 | toInt | formatNumber }}GB</div>
                  <div class="size-h6">USAGE</div>
              </div>
            </div>

        - type: repository
          repository: TechHutTV/homelab
          pull-requests-limit: 5
          issues-limit: 3
          commits-limit: 3

    - size: full
      widgets:
        - type: search
          autofocus: true

        - type: monitor
          cache: 1m
          title: Services
          sites:
            - title: Proxmox
              url: https://proxmox.your-domain.com/
              check-url: https://192.168.1.10:8006
              allow-insecure: true
              icon: di:proxmox
            - title: Immich
              url: https://immich.your-domain.com/
              check-url: http://192.168.1.20:2283
              icon: di:immich
            - title: Pi-hole
              url: https://pihole.your-domain.com/admin
              check-url: http://192.168.1.53
              icon: di:pi-hole
            - title: NZBGet
              url: https://nzbget.your-domain.com/
              check-url: http://192.168.1.30:6789
              icon: di:nzbget
              alt-status-codes:
                - 401
                - 403
```

Then add it to the `pages` list in `config/glance.yml`. Pages show up in the order you list them, so this makes Startpage the home page:

```yaml
pages:
  - $include: startpage.yml
  - $include: home.yml
```

Replace the IP addresses and domains with your own, and put the secrets in `.env`:

```dotenv
PIHOLE_PASSWORD=your-pihole-app-password
IMMICH_URL=http://192.168.1.20:2283
IMMICH_API_KEY=your-immich-api-key
```

Glance reloads the YAML files on its own, but it only reads `.env` when the container starts, so run `docker compose up -d` again after changing it.

### Page Settings

- `width: slim` keeps the page narrow, which looks great as a browser start page. A slim page allows at most two columns, and that's exactly what I use.
- `hide-desktop-navigation` controls the tab bar at the top. The preconfigured Startpage hides it. I have it set to `false`, which keeps the tabs visible so the Home page is one click away.
- `center-vertically: true` centers everything when the content is shorter than the window.
- Column order is the order on screen. The `small` column gives me that sidebar feel, and the `full` column takes the rest.

### Services: The Monitor Widget

This is probably the widget you'll use more than any other. Each site has a `title`, a `url`, and an `icon`, and Glance sends a request to it and shows OK and the response time when it gets a 200 back. A few properties made my setup work:

- **`check-url`**: My `url` is the proxied domain, which is what opens when I click the service. The `check-url` is the service's local IP and port, and that's what Glance checks.
- **`alt-status-codes`**: Some apps answer an unauthenticated request with a 401 or 403. NZBGet was one that wasn't cooperating, and Plex gave me trouble too because of how its authentication works. Listing those codes makes Glance count them as up.
- **`allow-insecure`**: Skips certificate validation, which is handy for self-signed certificates like the Proxmox web UI's.
- **`icon`**: `di:` pulls from [Dashboard Icons](https://github.com/homarr-labs/dashboard-icons), which is what I use. `si:` (Simple Icons), `sh:` (selfh.st icons), and `mdi:` (Material Design Icons) also work, or you can point at an image in your assets folder.

![The Glance monitor widget listing homelab services like Proxmox, Plex, Immich, and Jellyfin, each with an OK status and response time](/docs-static/img/2026/12/glance-home-server-dashboard/services-monitor-widget.jpg)

I have two monitor widgets, one for core services and one for the media stack. There's also `show-failing-only: true`, which only lists services that are down, and `style: compact` for a tighter layout. A small failing-only monitor at the bottom of a page is a neat way to only see something when there's a problem.

### Pi-hole: DNS Stats

In the video, my DNS stats widget was just `service`, `url`, and an API `token`. That was the Pi-hole v5 way. [Pi-hole v6](https://pi-hole.net/blog/2025/02/18/introducing-pi-hole-v6/) replaced the API, and Glance now has a separate `pihole-v6` service that logs in with a password. Use an application password rather than your admin password. You can make one in Pi-hole under **Settings > Web Interface / API > Configure app password**. If your Pi-hole has no password at all, leave the `password` line out.

On Pi-hole v5, keep `service: pihole` and use `token:` with the key from **Settings > API > Show API token**. The same widget also supports AdGuard Home and Technitium.

The Glance README notes that Pi-hole and AdGuard Home have fairly low rate limits by default. If widgets start timing out on a busy page, raising your DNS server's rate limit is the first thing to check.

### Immich Stats: The Custom API Widget

This one doesn't have a built-in widget. It uses `custom-api`, which fetches JSON from a URL and renders it with a template you write. I didn't write it, though. The Immich stats example is right in the Custom API section of the docs, and I copied and pasted it straight into my config. It worked first try.

The endpoint (`/api/server/statistics`) is [admin-only](https://api.immich.app/endpoints/server/getServerStatistics), so create the API key while signed in as an Immich admin. If you limit the key's permissions, it needs `server.statistics`. Glance makes the request from the server, so the key stays out of the browser, but it's still a key. Keep it in `.env`.

The docs have other examples to borrow, like Steam specials, and there's a [community widgets repository](https://github.com/glanceapp/community-widgets) full of custom ones. I'd love a live download-speed graph. If I were smart enough I'd just write it myself, and that's what `custom-api` is for.

### Search and Repository

The search widget defaults to DuckDuckGo. `search-engine` changes that, and `bangs` adds shortcuts like `!yt` for YouTube. Press **S** anywhere on the page to jump to the search bar.

The repository widget shows a GitHub repo's latest pull requests, issues, and commits. Unauthenticated GitHub requests are limited to 60 an hour, so if you see errors, add a read-only GitHub token with `token: ${GITHUB_TOKEN}`.

## Customize the Home Page

The `home.yml` from the template is basically the Home page from my video: a small column with the calendar, RSS, and Twitch channels; a full column with Hacker News and Lobsters grouped together, YouTube videos, and two subreddits; and a small column with weather, markets, and releases. Swap in your own feeds, channel IDs, subreddits, and repositories.

![The default Home page from the Docker Compose template running in a browser, with London weather, markets, Hacker News, and YouTube videos](/docs-static/img/2026/12/glance-home-server-dashboard/template-home-page.jpg)

The weather widget is the first thing to change, because the template points at London:

```yaml
        - type: weather
          location: "98101" # ZIP or postal code, or "City, Country"
          units: imperial
          hour-format: 12h
```

I used my ZIP code with `imperial` units. The weather data comes from Open-Meteo, so check your location with its [geocoding search](https://open-meteo.com/en/docs/geocoding-api) if it doesn't resolve. Glance uses the first match, and an invalid location stops it from starting. Quote numeric postal codes so YAML keeps them as text.

### Live Reload

This is my favorite part. In the video I removed SPY from the markets widget. Open `home.yml`, find the markets widget in the last column, and delete the entry:

```yaml
        - type: markets
          markets:
            - symbol: BTC-USD
              name: Bitcoin
            - symbol: NVDA
              name: NVIDIA
            - symbol: AAPL
              name: Apple
            - symbol: MSFT
              name: Microsoft
```

Save it (Ctrl+O in nano), refresh the browser, and SPY is gone. No restarting the container or the service. Glance watches its config files and reloads them on save, and a page refresh picks up the new version.

Two caveats from the docs. If you save something invalid, Glance logs the error and keeps running the last good config, so check the logs if a change doesn't show up. And every reload clears cached widget data, so saving over and over can get you rate limited by some APIs.

You can also validate the config from inside the running container:

```bash
docker compose exec glance /app/glance --config /app/config/glance.yml config:validate
```

## Themes

The [themes page](https://github.com/glanceapp/glance/blob/main/docs/themes.md) has ready-made color schemes. It wasn't obvious where the theme goes, but my guess that it belongs at the root of `glance.yml` was right, since it applies to every page. I was on Gruvbox Dark and tried Camouflage:

```yaml
theme:
  # Camouflage, from the themes list in the Glance docs
  background-color: 186 21 20
  contrast-multiplier: 1.2
  primary-color: 97 13 80
  custom-css-file: /assets/user.css

  # Optional: extra themes you can switch between from the theme picker
  presets:
    gruvbox-dark:
      background-color: 0 0 16
      primary-color: 43 59 81
      positive-color: 61 66 44
      negative-color: 6 96 59
```

Save, refresh, new theme. The colors are just HSL numbers, so you can tune them however you like.

![The Glance Startpage after switching to the Camouflage theme](/docs-static/img/2026/12/glance-home-server-dashboard/camouflage-theme-startpage.jpg)

The `presets` part is new since my video. Starting with v0.8.0, any presets you define show up in a theme picker on the page, so you can switch between them without editing the config. Set `disable-picker: true` if you don't want it. The `assets/user.css` file from the template is there for anything the theme settings can't do. Your browser caches it, so do a hard refresh (Ctrl+F5) after changing it.

## Lock It Down

The login feature arrived after my video, and it's worth using if more than your LAN can reach the dashboard. Generate a secret key and a password hash:

```bash
docker run --rm glanceapp/glance:v0.8.8 secret:make
docker run --rm glanceapp/glance:v0.8.8 password:hash 'your-strong-password'
```

The second command puts the password in your shell history, so clear that entry afterward.

Put the secret key in `.env` as `GLANCE_SECRET_KEY`, then add this to `glance.yml` with your username and the hash from the second command:

```yaml
auth:
  secret-key: ${GLANCE_SECRET_KEY}
  users:
    your-username:
      password-hash: paste-the-hash-from-password-hash-here
```

Glance blocks an IP after five failed logins in five minutes. If it sits behind a reverse proxy like Nginx Proxy Manager, also set this so it sees the real client IP:

```yaml
server:
  assets-path: /app/assets
  proxied: true
```

Only set `proxied: true` when a proxy is in front of Glance and passing `X-Forwarded-For`. Recreate the container with `docker compose up -d` so it picks up the new `.env` value.

## Final Thoughts

Glance became my favorite dashboard because it's simple and it's pretty. The single-file config is a big part of that. It's easy to carry that file with me no matter where I end up running it. Edits take effect on a refresh. And starting from a preconfigured page, then copying, pasting, and swapping in the things I care about, got me a good-looking homelab page fast.

The tradeoff is features. Homarr has more of them, deeper \*arr integration, and a web editor. That's a real plus, but I've found UI-based layout editing gets messy, since layouts can change with the window size. A few things I wanted, like a download-speed graph, would mean building a custom widget. If you'd rather click than write YAML, my [must-have home server services roundup](/must-have-home-server-services-2025) covers Homarr too.

For me, it's the one I keep coming back to. Start with the template, get the monitor widget pointed at your services, and build from there. With all that, I do hope you found this useful. Have a great one.
