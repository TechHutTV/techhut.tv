I wanted Seafile running in its own VM, with my files on Unraid and HTTPS handled by the Nginx Proxy Manager instance I already use. The idea is pretty simple. The part that takes a minute is getting the storage mount, the database, the document editor, and the notification service to agree on where things live.

I'm walking through that setup with Seafile Community Edition 13, Fedora Server, and Docker Compose. SeaDoc is in there so you can edit documents in the browser, and Seafile's notification server is in there so library updates show up live. You reach all of it through one address, like `https://seafile.example.com`.

Once Seafile is working, you can add OnlyOffice for Word, Excel, and PowerPoint files. If you're moving existing files over, that's my separate [Nextcloud-to-Seafile migration guide](/migrate-nextcloud-files-to-seafile).

I ran Seafile **13.0.25** and SeaDoc **2.0.9**. The examples follow the 13.x configuration and those update tags. I put the services in one Compose file so you can follow along without bouncing between samples. This is a customized version of the [official Seafile 13 Docker setup](https://manual.seafile.com/13.0/setup/setup_ce_by_docker/), with a reverse proxy I already had, local disk for the database, and Unraid for the files.

## What we're building

Nginx Proxy Manager, NPM if you already run it, stays on the server you already have. It takes the HTTPS connection and forwards it to port **8080** on the Seafile VM. A small NGINX container inside that VM sends each request to the right service.

```text
Your browser or Seafile client
          |
          | HTTPS: seafile.example.com
          v
Existing Nginx Proxy Manager
          |
          | HTTP: 192.168.1.50:8080
          v
NGINX gateway in the Fedora VM
          |
          +-- Seafile: files, accounts, and web interface
          +-- SeaDoc: collaborative document editor
          +-- Notification server: real-time updates

VM local disk                     Unraid share, mounted in the VM
/srv/seafile                      /mnt/seafile
  Compose files                     Seafile files and configuration
  Live MariaDB database             SeaDoc persistent files
```

That base setup is six containers: Seafile, SeaDoc, the notification server, MariaDB, Redis, and the NGINX gateway. Only the gateway publishes a port on the VM. If you add OnlyOffice later, that's a seventh container, and you reach it through `/office/` on the same domain.

## Before you start

I'm assuming a **new, dedicated Fedora Server VM on Unraid**. This is a fresh install, so don't paste these files over a Seafile box that's already running without reading its config first.

You'll need:

- An x86-64 Fedora Server VM. I used Fedora 44, four virtual CPUs across two physical cores, and **4 GB of RAM** for the base setup.
- A local virtual disk with room for Fedora, container images, and the database. I started with **64 GB**, then expanded it to **128 GB** for OnlyOffice and a multi-terabyte migration. If you're following both guides, start with the larger disk and check the migration cache requirements below.
- An Unraid user share named `seafile`, with enough space for your files.
- An existing NPM instance that can reach the VM over your network.
- A domain you control, with its Seafile hostname pointing to NPM.
- A Fedora account with `sudo` access and basic familiarity with SSH.

Seafile's own numbers for CE are two CPU cores and 2 GB of memory, and the extra services need more than that. Check their [system requirements](https://manual.seafile.com/13.0/setup/system_requirements/) if you're sizing something bigger.

Use these examples consistently as you go:

| Setting | Example | What to use |
| --- | --- | --- |
| VM address | `192.168.1.50` | Your Fedora VM's LAN address |
| Public hostname | `seafile.example.com` | Your actual Seafile domain |
| Administrator | `you@example.com` | Your email address |
| Unraid mount tag | `seafile` | Must match the VM share setting |

Go ahead and reserve the VM's address in your router or DHCP server. That way NPM's forwarding target doesn't change after a reboot.

Unless a step specifically says **Unraid**, **NPM**, or **your computer**, run the commands in the **Fedora VM over SSH**. I'm using `nano` to edit files. Save with **Ctrl+O**, press **Enter**, then exit with **Ctrl+X**.

Install the few command-line tools we'll use:

```bash
sudo dnf install -y nano curl openssl
```

## 1. Prepare the VM in Unraid

Shut the VM down before you change its hardware settings. In Unraid's VM editor, set the CPU mode to **Host Passthrough** and give it at least two CPU cores. My setup uses two cores and their matching threads, so Fedora sees four virtual CPUs.

That fixed a problem I hit during install. The VM's generic QEMU CPU model hid instructions a bundled Python dependency needed. The login page loaded, but an API request came back with an error about `X86_V2`. Host Passthrough exposed the real CPU features. Do note that the physical CPU still has to support the instructions the software wants.

Add the Unraid share with these settings:

| Unraid VM setting | Value |
| --- | --- |
| Unraid Share Mode | `9p Mode` |
| Unraid Share | `User:seafile` |
| Unraid Source Path | `/mnt/user/seafile/` |
| Unraid Mount Tag | `seafile` |

Start the VM and reconnect with SSH.

## 2. Choose where the data lives

| Path inside Fedora | Underlying storage | Purpose |
| --- | --- | --- |
| `/srv/seafile` | VM's local virtual disk | Compose project, environment file, and proxy configuration |
| `/srv/seafile/mysql` | VM's local virtual disk | Live MariaDB database |
| `/mnt/seafile/seafile-data` | Unraid share | Seafile's stored file blocks, application configuration, and logs |
| `/mnt/seafile/seadoc-data` | Unraid share | SeaDoc's persistent directory, including logs |

MariaDB stays on the VM's local Linux filesystem because it does a lot of small reads and writes. Mounting the Unraid share at `/mnt/seafile` puts the bigger file storage on the NAS. Making a folder with that name on the VM disk doesn't move anything there.

If you're also following the [migration guide](/migrate-nextcloud-files-to-seafile), the client's index and temporary blocks go under `/srv/seafile/migration` on the local disk. Those are working files for the copy. Seafile's permanent file blocks still go to `/mnt/seafile` on Unraid.

Seafile stores uploads in its own block format. Add existing documents through the web interface or the client so they show up in your libraries.

## 3. Mount the Unraid share inside Fedora

The 9p share comes from Unraid into the VM through the virtual hardware. You don't type an SMB server address, and you don't mount it with Unraid's IP. The name `seafile` below is the **mount tag** from the VM settings. Linux documents this transport in its [9p filesystem guide](https://docs.kernel.org/filesystems/9p.html).

Create the mount point and try the mount:

```bash
sudo mkdir -p /mnt/seafile
sudo mount -t 9p -o trans=virtio,version=9p2000.L,cache=none seafile /mnt/seafile
df -h /mnt/seafile
```

You should see `seafile` in the **Filesystem** column and `/mnt/seafile` under **Mounted on**. If it shows the VM's root filesystem instead, the share isn't mounted. Check the Unraid mount tag before you create application folders.

Make the mount stick around after a reboot. Back up the existing file, then open it:

```bash
sudo cp -a /etc/fstab /etc/fstab.before-seafile
sudo nano /etc/fstab
```

Add this as **one new line**, keeping the existing entries:

```text
seafile /mnt/seafile 9p trans=virtio,version=9p2000.L,cache=none,rw,nofail,x-systemd.mount-timeout=30s 0 0
```

Save the file, reload systemd, and apply the mount entries:

```bash
sudo systemctl daemon-reload
sudo mount -a
```

`nofail` lets Fedora finish booting if the share is unavailable. Later we'll tell Docker and Seafile they require the mount. You can still reach the VM to fix storage, and the app won't write into an empty local folder that only looks like the share.

## 4. Install Docker and create the folders

Install Docker with the quickstart script, then enable the service on Fedora. My [Docker basics guide](/7-docker-basics-for-beginners) covers the install, plus how containers, volumes, and Compose work.

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
```

The script includes the Compose plugin. We'll use `sudo docker compose` for the rest of this guide.

Check your user and group IDs:

```bash
id
```

Look for `uid=` and `gid=` in the output. The commands below use **1000:1000**. Swap those numbers if yours are different. Create the project and database folders, then give your user ownership of the project folder so you can edit the config files:

```bash
sudo mkdir -p /srv/seafile/mysql
sudo chown 1000:1000 /srv/seafile
sudo chmod 750 /srv/seafile /srv/seafile/mysql
```

With the Unraid share mounted from the previous step, create its application directories:

```bash
sudo mkdir -p /mnt/seafile/seafile-data/seafile/logs
sudo mkdir -p /mnt/seafile/seadoc-data
cd /srv/seafile
```

That `chown` only hits the project folder. MariaDB manages ownership inside `mysql`, so leave that directory alone and let the container handle it.

## 5. Create the environment file

The `.env` file holds the settings Compose drops into the container config. Generate a separate random value for each of the five blank password and key fields in the template below. Run this once per field and save the values in your password manager:

```bash
openssl rand -hex 32
```

Create the file in `/srv/seafile`:

```bash
nano .env
```

Paste this template and fill in the blank fields with your generated values:

```dotenv
COMPOSE_PROJECT_NAME=seafile

SEAFILE_BIND_IP=192.168.1.50
SEAFILE_SERVER_HOSTNAME=seafile.example.com
SEAFILE_SERVER_PROTOCOL=https
TIME_ZONE=America/Los_Angeles

SEAFILE_IMAGE=seafileltd/seafile-mc:13.0-latest
SEAFILE_DB_IMAGE=mariadb:10.11
SEAFILE_REDIS_IMAGE=redis:7.4-alpine
SEADOC_IMAGE=seafileltd/sdoc-server:2.0-latest
NOTIFICATION_SERVER_IMAGE=seafileltd/notification-server:13.0-latest
GATEWAY_IMAGE=nginx:stable-alpine

SEAFILE_VOLUME=/mnt/seafile/seafile-data
SEADOC_VOLUME=/mnt/seafile/seadoc-data
SEAFILE_MYSQL_VOLUME=/srv/seafile/mysql

JWT_PRIVATE_KEY=
SEAFILE_MYSQL_DB_PASSWORD=
INIT_SEAFILE_MYSQL_ROOT_PASSWORD=
REDIS_PASSWORD=
INIT_SEAFILE_ADMIN_EMAIL=you@example.com
INIT_SEAFILE_ADMIN_PASSWORD=

ENABLE_SEADOC=true
ENABLE_NOTIFICATION_SERVER=true
```

Replace `SEAFILE_BIND_IP`, `SEAFILE_SERVER_HOSTNAME`, and `INIT_SEAFILE_ADMIN_EMAIL` with your values. Set your time zone too. The hostname is just the domain, no `https://` and no trailing slash.

Save the file, then restrict it to your user:

```bash
chmod 600 .env
```

`INIT_SEAFILE_ADMIN_PASSWORD` is the password you'll use the first time you log in. Leave `SEAFILE_SERVER_PROTOCOL=https`. That's the address your browser uses, even though NPM talks to the VM over HTTP.

Compose shares `JWT_PRIVATE_KEY` with Seafile, SeaDoc, and notifications so they can authenticate with each other.

The `INIT_` administrator settings only set up a new install. Changing them later doesn't reset a password that's already there. Keep `.env` private, and keep it out of Git.

## 6. Add the Compose file

Create the file:

```bash
nano compose.yaml
```

Paste the whole config below. It's long because it includes all six services, the health checks, and the storage mounts written out. You shouldn't need to edit it if you used the paths above and filled in `.env`.

```yaml
services:
  db:
    image: ${SEAFILE_DB_IMAGE}
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${INIT_SEAFILE_MYSQL_ROOT_PASSWORD:?Set in .env}
      MYSQL_LOG_CONSOLE: "true"
      MARIADB_AUTO_UPGRADE: "1"
    volumes:
      - type: bind
        source: ${SEAFILE_MYSQL_VOLUME}
        target: /var/lib/mysql
        bind:
          create_host_path: false
    healthcheck:
      test: ["CMD", "/usr/local/bin/healthcheck.sh", "--connect", "--mariadbupgrade", "--innodb_initialized"]
      interval: 20s
      timeout: 5s
      retries: 10
      start_period: 30s
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  redis:
    image: ${SEAFILE_REDIS_IMAGE}
    restart: unless-stopped
    environment:
      REDIS_PASSWORD: ${REDIS_PASSWORD:?Set in .env}
    command:
      - /bin/sh
      - -c
      - exec redis-server --requirepass "$$REDIS_PASSWORD" --save "" --appendonly no
    healthcheck:
      test: ["CMD-SHELL", "REDISCLI_AUTH=\"$$REDIS_PASSWORD\" redis-cli ping | grep -q PONG"]
      interval: 20s
      timeout: 5s
      retries: 5
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  seafile:
    image: ${SEAFILE_IMAGE}
    restart: unless-stopped
    volumes:
      - type: bind
        source: ${SEAFILE_VOLUME}
        target: /shared
        bind:
          create_host_path: false
    environment:
      SEAFILE_MYSQL_DB_HOST: db
      SEAFILE_MYSQL_DB_PORT: "3306"
      SEAFILE_MYSQL_DB_USER: seafile
      SEAFILE_MYSQL_DB_PASSWORD: ${SEAFILE_MYSQL_DB_PASSWORD:?Set in .env}
      INIT_SEAFILE_MYSQL_ROOT_PASSWORD: ${INIT_SEAFILE_MYSQL_ROOT_PASSWORD:?Set in .env}
      SEAFILE_MYSQL_DB_CCNET_DB_NAME: ccnet_db
      SEAFILE_MYSQL_DB_SEAFILE_DB_NAME: seafile_db
      SEAFILE_MYSQL_DB_SEAHUB_DB_NAME: seahub_db
      INIT_SEAFILE_ADMIN_EMAIL: ${INIT_SEAFILE_ADMIN_EMAIL:?Set in .env}
      INIT_SEAFILE_ADMIN_PASSWORD: ${INIT_SEAFILE_ADMIN_PASSWORD:?Set in .env}
      SEAFILE_SERVER_HOSTNAME: ${SEAFILE_SERVER_HOSTNAME:?Set in .env}
      SEAFILE_SERVER_PROTOCOL: ${SEAFILE_SERVER_PROTOCOL}
      TIME_ZONE: ${TIME_ZONE}
      JWT_PRIVATE_KEY: ${JWT_PRIVATE_KEY:?Set in .env}
      NON_ROOT: "false"
      CACHE_PROVIDER: redis
      REDIS_HOST: redis
      REDIS_PORT: "6379"
      REDIS_PASSWORD: ${REDIS_PASSWORD:?Set in .env}
      ENABLE_SEADOC: ${ENABLE_SEADOC}
      SEADOC_SERVER_URL: ${SEAFILE_SERVER_PROTOCOL}://${SEAFILE_SERVER_HOSTNAME}/sdoc-server
      ENABLE_NOTIFICATION_SERVER: ${ENABLE_NOTIFICATION_SERVER}
      INNER_NOTIFICATION_SERVER_URL: http://notification-server:8083
      NOTIFICATION_SERVER_URL: ${SEAFILE_SERVER_PROTOCOL}://${SEAFILE_SERVER_HOSTNAME}/notification
      ENABLE_SEAFILE_AI: "false"
      ENABLE_FACE_RECOGNITION: "false"
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS -H \"Host: $$SEAFILE_SERVER_HOSTNAME\" http://localhost:80/api2/server-info/ > /dev/null"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 180s
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  seadoc:
    image: ${SEADOC_IMAGE}
    restart: unless-stopped
    volumes:
      - type: bind
        source: ${SEADOC_VOLUME}
        target: /shared
        bind:
          create_host_path: false
    environment:
      DB_HOST: db
      DB_PORT: "3306"
      DB_USER: seafile
      DB_PASSWORD: ${SEAFILE_MYSQL_DB_PASSWORD:?Set in .env}
      DB_NAME: seahub_db
      TIME_ZONE: ${TIME_ZONE}
      JWT_PRIVATE_KEY: ${JWT_PRIVATE_KEY:?Set in .env}

      SEAHUB_SERVICE_URL: http://seafile

      db:
        condition: service_healthy
      seafile:
        condition: service_healthy

      driver: local

        source: ${SEAFILE_VOLUME}/seafile/logs
        target: /shared/seafile/logs
        bind:
          create_host_path: false
    environment:
      SEAFILE_MYSQL_DB_HOST: db
      SEAFILE_MYSQL_DB_PORT: "3306"

      SEAFILE_MYSQL_DB_CCNET_DB_NAME: ccnet_db
      SEAFILE_MYSQL_DB_SEAFILE_DB_NAME: seafile_db
      JWT_PRIVATE_KEY: ${JWT_PRIVATE_KEY:?Set in .env}
    depends_on:
      db:
        condition: service_healthy
      seafile:
        condition: service_healthy
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"

  gateway:
    image: ${GATEWAY_IMAGE}
    restart: unless-stopped
    ports:
      - "${SEAFILE_BIND_IP:?Set in .env}:8080:80"
    volumes:
      - type: bind
        source: /srv/seafile/gateway.conf
        target: /etc/nginx/conf.d/default.conf
        read_only: true
        bind:
          create_host_path: false
    depends_on:
      seafile:
        condition: service_healthy
      seadoc:
        condition: service_started
      notification-server:
        condition: service_started
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1/api2/server-info/"]
      interval: 30s
      timeout: 10s
      retries: 3
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"
```

Compose creates a private network for this project on its own. On that network, the service name `db` resolves to MariaDB, `seafile` resolves to Seafile, and so on. These names aren't public DNS records you need to create.

The `source` of each bind mount is a path on Fedora. The `target` is where that directory shows up inside the container. `create_host_path: false` turns a missing source directory into an error instead of quietly creating one. The systemd setup below makes startup wait for the Unraid mount.

The logging settings cap Docker's own container logs. Application log files written into the shared data directories rotate on their own, and they still need disk space.

## 7. Add the internal NGINX gateway

Create the gateway configuration:

```bash
nano gateway.conf
```

Paste this file exactly as shown. It picks up the incoming domain on its own, so there's no example hostname to replace here.

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

server {
    listen 80 default_server;
    server_name _;
    server_tokens off;

    client_max_body_size 0;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_buffering off;
    proxy_request_buffering off;

    location /sdoc-server/ {
        proxy_pass http://seadoc:80/;
    }

    location /socket.io {
        proxy_pass http://seadoc:80;
    }

    location = /notification {
        proxy_pass http://notification-server:8083/;
    }

    location /notification/ {
        proxy_pass http://notification-server:8083/;
    }

    location / {
        proxy_pass http://seafile:80;
    }
}
```

The gateway keeps the NPM side pretty simple: one domain and one forwarding port. Seafile gets the normal application requests, and the other locations handle SeaDoc and notifications.

Keep the trailing slashes as shown. For example, `/notification/ping` needs to arrive at the notification container as `/ping`. The WebSocket headers are what let the add-ons keep those persistent connections open. This follows the routing in Seafile's [external reverse proxy guide](https://manual.seafile.com/13.0/setup/use_other_reverse_proxy/) and [NGINX's WebSocket documentation](https://nginx.org/en/docs/http/websocket.html).

We forward `X-Forwarded-Proto https` because NPM is the one handling the encrypted browser connection. Port 8080 is an HTTP backend for your trusted network. Don't forward it straight from your internet router.

Check the Compose configuration without printing its resolved passwords:

```bash
sudo docker compose config --quiet
sudo docker compose pull
```

No output from `config --quiet` means validation passed. Image downloads can take a few minutes, so just let it run.

## 8. Make startup wait for Unraid

If Docker starts before the share mounts, container restart policies can bring the app back before your storage is ready.

Since this is a **dedicated Seafile VM**, we'll make the Docker daemon itself depend on the share. That affects every Docker container on the VM. On a shared Docker host, you'd need a startup setup that accounts for the other apps too.

Create a Docker service override:

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo nano /etc/systemd/system/docker.service.d/seafile-storage.conf
```

```ini
[Unit]
RequiresMountsFor=/mnt/seafile
BindsTo=mnt-seafile.mount
After=mnt-seafile.mount
```

Now create a systemd service for the Compose project:

```bash
sudo nano /etc/systemd/system/seafile.service
```

```ini
[Unit]
Description=Seafile Docker Compose stack
Requires=docker.service
Wants=network-online.target
After=docker.service network-online.target mnt-seafile.mount
RequiresMountsFor=/mnt/seafile /srv/seafile
BindsTo=mnt-seafile.mount
PartOf=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/srv/seafile
ExecStart=/usr/bin/docker compose up -d --wait --wait-timeout 360
ExecStop=/usr/bin/docker compose down --timeout 60
TimeoutStartSec=600
TimeoutStopSec=180

[Install]
WantedBy=multi-user.target
```

This tells systemd where the project lives and starts the containers after the share mounts. `BindsTo` stops the dependent service if systemd sees the mount disappear.

Start everything:

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
sudo systemctl enable --now seafile.service
sudo docker compose ps
```

The first start creates the databases, the initial administrator, and the application config. Give it a few minutes. The database, Redis, Seafile, and gateway should become healthy. SeaDoc and the notification server should be running. We'll check the add-ons through HTTPS in a minute.

If startup fails, read the logs before you change anything:

```bash
sudo journalctl -u seafile.service -n 80 --no-pager
sudo docker compose logs --tail=100 db seafile
```

If the first start is just slow, read the logs and retry with `sudo systemctl restart seafile.service` once you've fixed the actual problem. You don't need to delete the database and start over.

## 9. Point Nginx Proxy Manager at the VM

In your **existing NPM interface**, create a Proxy Host with these settings:

| NPM field | Value |
| --- | --- |
| Domain Names | Your domain, such as `seafile.example.com` |
| Scheme | `http` |
| Forward Hostname / IP | Your Fedora VM, such as `192.168.1.50` |
| Forward Port | `8080` |
| Websockets Support | Enabled |
| Cache Assets | Disabled |

In the **SSL** tab, select or request a valid certificate for the domain and enable **Force SSL**. Your DNS and certificate check need to work with the NPM setup you already have.

In the **Advanced** tab, add:

```nginx
client_max_body_size 0;
proxy_request_buffering off;
proxy_buffering off;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
```

These settings take off NGINX's request-body size cap and give transfers longer timeouts. Something sitting in front of NPM, like a CDN, can still have its own limits.

You don't need extra NPM Custom Locations with this config. The gateway in the VM already handles `/sdoc-server/`, `/socket.io`, and `/notification`.

Save the proxy host and open your HTTPS domain. Log in with the email and the administrator password you generated in `.env`. And there we go, you should be looking at Seafile.

## 10. Upload files and try document editing

Before you drop in your real files, make a temporary library and upload a small document or image. Download it again and check the contents. Then try a larger file like the ones you store.

### SeaDoc: documents in the browser

In a library, use the **New** menu and create a SeaDoc document. Type a few lines, wait for it to finish saving, close it, then open it again. Your text should still be there. If you want to collaborate, share a test document with a second account and try editing from two browser sessions.

[SeaDoc](https://manual.seafile.com/13.0/extension/setup_seadoc/) edits Seafile's `.sdoc` documents, which are nice for notes and shared docs. To edit uploaded Office files like `.docx` in the browser, add OnlyOffice after the base setup below.

### Notifications: live connections, separate from email

The [notification server](https://manual.seafile.com/13.0/extension/notification-server/) uses WebSockets to tell supported clients when a library changes. We turn it on in Seafile, run its container, and route its public URL through the gateway.

This service doesn't set up invitation emails, password-reset emails, or an SMTP server. Those live under the manual's **Configuration → Email Sending** section.

## A quick note on backups

Before you add your real files, back up **Seafile's databases, the stored file data, and the config**, including `.env` and any OnlyOffice settings. Copying the Unraid share by itself misses the live database on the VM. Follow [Seafile's backup instructions](https://manual.seafile.com/13.0/administration/backup_recovery/) if you want a consistent copy.

My [Proxmox Backup Server guide](/proxmox-backup-server-complete-guide#backing-up-docker-with-pbs-client) covers backing up Docker hosts and keeping an offsite copy. That's a good next step once Seafile is working. Do test a restore before you trust it.

## 11. Reboot and check the complete setup

Once file uploads and document editing work, reboot the VM:

```bash
sudo reboot
```

Reconnect with SSH and check that the share mounted and the containers came back:

```bash
df -h /mnt/seafile
cd /srv/seafile
sudo docker compose ps
```

Open your HTTPS domain again, reopen your test document, and download a test file. That confirms the app came back with the data you already put in it.

## Optional: add OnlyOffice for Office documents

I went with [OnlyOffice Docs](https://manual.seafile.com/13.0/extension/only_office/) for Word, Excel, and PowerPoint files, and I tested opening, saving, and reopening a DOCX. We'll add its **Document Server** to the Compose project you already have, next to SeaDoc. [Collabora Online](https://manual.seafile.com/13.0/extension/collabora_online/) is the other option if you'd rather use that.

I bumped the VM to **8 GB of RAM** for this combined setup. [OnlyOffice's Docker requirements](https://helpcenter.onlyoffice.com/docs/installation/docs-community-install-docker.aspx) list 4 GB of RAM, 40 GB of free disk space, and at least 4 GB of swap. I ended up on a **128 GB virtual disk** so there was room for the combined install and the migration cache. Check free space inside Fedora. The disk's advertised size includes the OS, images, database, and whatever else is already on there.

### Create OnlyOffice's folders

Keep its config, fonts, logs, and working cache on the VM's local disk at `/srv/seafile/onlyoffice`. Saved documents go back to Seafile on Unraid.

Create the local directories:

```bash
cd /srv/seafile
mkdir -p onlyoffice/{data,lib,logs,fonts}
nano onlyoffice/local-production-linux.json
```

Paste this little config file. It tells OnlyOffice to send saved document versions back every five minutes while you're editing:

```json
{
  "services": {
    "CoAuthoring": {
      "autoAssembly": {
        "enable": true,
        "interval": "5m"
      }
    }
  }
}
```

Make this particular file readable by the container's worker processes:

```bash
chmod 644 onlyoffice/local-production-linux.json
```

It has no passwords in it. Keep `.env` private at mode `600`. Don't slap `644` on your other config files. I made this JSON file too locked down at first, and OnlyOffice's document service and converter wouldn't start.

### Add the container and its secret

Generate a separate JWT secret for OnlyOffice, then open `.env`:

```bash
cd /srv/seafile
openssl rand -hex 32
nano .env
```

Add these two lines at the end and paste the generated value after `ONLYOFFICE_JWT_SECRET=`. If those settings are already there, keep the secret you already have.

```dotenv
ONLYOFFICE_IMAGE=onlyoffice/documentserver:9.4.0.1
ONLYOFFICE_JWT_SECRET=
```

Save `.env`, then open the Compose file:

```bash
nano compose.yaml
```

Add the following **inside the existing `services:` section**, lined up with `seafile:`, `db:`, and `gateway:`. Don't add another `services:` heading. All seven services use the same default Compose network.

```yaml
  onlyoffice:
    image: ${ONLYOFFICE_IMAGE:?Set in .env}
    restart: unless-stopped
    stop_grace_period: 6m
    environment:
      JWT_ENABLED: "true"
      JWT_SECRET: ${ONLYOFFICE_JWT_SECRET:?Set in .env}
      JWT_HEADER: Authorization
      JWT_IN_BODY: "true"
      ALLOW_PRIVATE_IP_ADDRESS: "true"
      ALLOW_META_IP_ADDRESS: "false"
      USE_UNAUTHORIZED_STORAGE: "false"
      EXAMPLE_ENABLED: "false"
      ADMINPANEL_ENABLED: "false"
      TZ: ${TIME_ZONE}
    volumes:
      - type: bind
        source: /srv/seafile/onlyoffice/data
        target: /var/www/onlyoffice/Data
        bind:
          create_host_path: false
      - type: bind
        source: /srv/seafile/onlyoffice/lib
        target: /var/lib/onlyoffice
        bind:
          create_host_path: false
      - type: bind
        source: /srv/seafile/onlyoffice/logs
        target: /var/log/onlyoffice
        bind:
          create_host_path: false
      - type: bind
        source: /srv/seafile/onlyoffice/fonts
        target: /usr/share/fonts/truetype/custom
        bind:
          create_host_path: false
      - type: bind
        source: /srv/seafile/onlyoffice/local-production-linux.json
        target: /etc/onlyoffice/documentserver/local-production-linux.json
        read_only: true
        bind:
          create_host_path: false
    logging:
      driver: local
      options:
        max-size: "10m"
        max-file: "3"
    healthcheck:
      test: ["CMD-SHELL", "test \"$$(curl -fsS http://127.0.0.1/healthcheck)\" = true"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 180s
```

`ALLOW_PRIVATE_IP_ADDRESS` lets OnlyOffice fetch documents and send saves back when your Seafile hostname points at NPM's LAN address. HTTPS certificate checks stay on.

### Route `/office/` through the existing gateway

Open `/srv/seafile/gateway.conf`. Add these locations **inside the existing `server` block**, above `location /`:

```nginx
    location = /office {
        return 301 /office/;
    }

    location /office/ {
        resolver 127.0.0.11 valid=30s ipv6=off;
        set $office_backend http://onlyoffice:80;
        rewrite ^/office/(.*)$ /$1 break;
        proxy_pass $office_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Host $host/office;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
    }
```

The browser asks for `/office/...`, and the gateway strips that prefix before it forwards to Document Server. The forwarded host includes `/office` so the editor builds the right public URLs, following [OnlyOffice's virtual-path proxy example](https://github.com/ONLYOFFICE/document-server-proxy/blob/master/nginx/proxy-to-virtual-path.conf). Docker's DNS resolver lets NGINX look up the optional service when a request shows up.

Keep this path as **`/office/`**. Seafile uses `/onlyoffice/` for its own integration endpoints, so sending that whole prefix to Document Server breaks callbacks. Your NPM proxy host still forwards to the same VM address and port **8080**, with WebSockets on. You don't need another domain or a Custom Location.

Validate and start the editor, then reload the gateway:

```bash
cd /srv/seafile
sudo docker compose config --quiet
sudo docker compose pull onlyoffice
sudo docker compose up -d --wait --wait-timeout 360 onlyoffice
sudo docker compose exec gateway nginx -t
sudo docker compose exec gateway nginx -s reload
```

Once startup and the NGINX config check succeed, connect the editor to Seafile below. If either command fails, check `sudo docker compose logs --tail=100 onlyoffice gateway`.

### Enable OnlyOffice in Seafile

Open `.env` in nano and copy the value of `ONLYOFFICE_JWT_SECRET`. Then open Seafile's generated settings file:

```bash
sudo nano /mnt/seafile/seafile-data/seafile/conf/seahub_settings.py
```

Add these settings at the end. Replace the example domain and paste the **same OnlyOffice secret** between the quotes. If these settings already exist, edit them instead of adding duplicates.

```python
ENABLE_ONLYOFFICE = True
ONLYOFFICE_APIJS_URL = 'https://seafile.example.com/office/web-apps/apps/api/documents/api.js'
ONLYOFFICE_JWT_SECRET = 'PASTE_THE_ONLYOFFICE_JWT_SECRET_FROM_ENV'
ONLYOFFICE_FORCE_SAVE = True
VERIFY_ONLYOFFICE_CERTIFICATE = True
ONLYOFFICE_FILE_EXTENSION = (
    'doc', 'docx', 'ppt', 'pptx', 'xls', 'xlsx',
    'odt', 'fodt', 'odp', 'fodp', 'ods', 'fods', 'ppsx', 'pps', 'csv'
)
ONLYOFFICE_EDIT_FILE_EXTENSION = ('docx', 'pptx', 'xlsx', 'csv')
```

These settings follow the [Seafile 13 integration](https://manual.seafile.com/13.0/extension/only_office/). The file lists turn on Office previews and editing, and PDFs stay with Seafile's existing viewer.

Restart Seafile to load the settings:

```bash
sudo chmod 600 /mnt/seafile/seafile-data/seafile/conf/seahub_settings.py
sudo docker compose restart seafile
sudo docker compose ps
```

Wait for Seafile to come back healthy. Upload a throwaway `.docx` to a test library, open it, change a sentence, save, close the editor, and open it again. Then download that document and open the copy too. A working editor page doesn't mean the save made it back into Seafile.

### Give active documents time to save during shutdown

OnlyOffice has a [shutdown preparation command](https://github.com/ONLYOFFICE/Docker-DocumentServer#stopping-docker-documentserver) that sends pending document changes back before it stops. Add a drop-in to the Seafile service so that command runs while Seafile and the gateway are still up:

```bash
sudo mkdir -p /etc/systemd/system/seafile.service.d
sudo nano /etc/systemd/system/seafile.service.d/onlyoffice.conf
```

```ini
[Service]
ExecStop=
ExecStop=-/usr/bin/docker compose exec -T onlyoffice documentserver-prepare4shutdown.sh
ExecStop=/usr/bin/docker compose down --timeout 360
TimeoutStopSec=900
```

The empty `ExecStop=` clears the shorter stop command from the base unit. The commands after that prepare documents for shutdown, then stop the stack. The leading `-` lets systemd keep stopping if the editor is already gone. Check the journal if that preparation step reports an error.

```bash
sudo systemctl daemon-reload
```

Use `sudo systemctl stop seafile.service` or `sudo systemctl restart seafile.service` for planned maintenance so this step runs. Give the VM time to shut down normally, and close editing sessions before you do maintenance. This won't save you from a sudden power loss. Documents that already saved stay in Seafile's data on Unraid.

## A few problems worth checking first

| Symptom | First thing to check |
| --- | --- |
| `mount` can't find the 9p share | The Unraid VM mount tag must be `seafile`, and the share must be attached to this VM. |
| Docker won't start after a reboot | Check `df -h /mnt/seafile` and `sudo journalctl -u mnt-seafile.mount`. The storage dependency may be doing its job. |
| NPM shows a 502 error | Confirm the VM's reserved IP, port 8080, and `docker compose ps`. NPM needs a network route to that address. |
| Login page loads but requests return 500 | Read Seafile's logs. If they mention missing `X86_V2` CPU support, check the VM CPU mode. |
| SeaDoc opens but won't connect or save | Check `/sdoc-server/`, WebSocket support, the shared JWT, and the `seadoc` logs. |
| DOCX says online view isn't applicable | SeaDoc edits `.sdoc` files. Complete the optional OnlyOffice integration for Office previews. |
| OnlyOffice reports an invalid security token | The OnlyOffice JWT in `.env` and `seahub_settings.py` must match; restart the affected services after correcting it. |
| OnlyOffice opens but can't download or save | Check its access to the public Seafile hostname, certificate validation, private-IP setting, and `/office/` routing. |
| OnlyOffice stays unhealthy | Check its logs, VM resources, and that `local-production-linux.json` is readable at mode `644`. |
| Notification ping works but live updates don't | Check the `/notification` WebSocket connection for status 101. |
| Large uploads fail with 413 or time out | Check the body-size and timeout settings in both NPM and the gateway, plus any upstream proxy limits. |
| A bind mount reports permission denied | Check the specific directory's ownership and any SELinux denials before changing permissions. |

I left SELinux enforcing on this Fedora box. Don't turn it off as a general install step, and don't add `:Z` relabeling to the 9p mounts unless you know that filesystem supports the labels your Docker config needs.

### If an editor or live updates won't connect

These endpoint checks help narrow down a proxy problem. Run them from your computer or the VM, and swap in your domain:

```bash
curl -fsS https://seafile.example.com/api2/ping/
curl -fsS https://seafile.example.com/sdoc-server/
curl -fsS https://seafile.example.com/notification/ping
```

You want `pong`, a SeaDoc welcome response, and a response containing `"ret":"pong"`, in that order. If HTTPS validation fails, fix the certificate or hostname. Don't paper over it with `-k`.

If you installed OnlyOffice, check its route too:

```bash
curl -fsS https://seafile.example.com/office/healthcheck
curl -fsS -o /dev/null https://seafile.example.com/office/web-apps/apps/api/documents/api.js
```

The health check should return `true`, and the second command should finish without an error. If either fails, check `sudo docker compose logs --tail=100 onlyoffice gateway` from `/srv/seafile`.

If the pings work but SeaDoc or live updates still won't connect, open your browser's developer tools, select **Network**, filter for **WS**, and reload the page. Look for `/notification` and, while you're editing a SeaDoc document, `/socket.io`. A successful WebSocket upgrade has status **101**.
