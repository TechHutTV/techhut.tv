I don't want to use DeepSeek's hosted web version, because everything you type into it ends up stored on servers in China. The part I like about DeepSeek R1 is that the weights are open. You can download the model, host it yourself, and it never needs to talk to the internet.

So we're putting DeepSeek R1 on a Raspberry Pi 5. We'll use [Ollama](https://ollama.com) to download and run the model, chat with it in the terminal, and then add [Open WebUI](https://github.com/open-webui/open-webui) so you get a ChatGPT-style interface in your browser, including PDF uploads.

A Pi is not the fastest way to run this. The exact same steps work on a regular Linux desktop or server, and Ollama also runs on Windows and macOS. Chances are you'll get much better performance on any of those. I'm doing it on a Pi partly because it makes a nice tutorial, and partly to show that the smallest distilled model really does run on one. You'll get answers. They just won't arrive quickly.

The written steps have been updated for [Ollama v0.40.16](https://github.com/ollama/ollama/releases/tag/v0.40.16) (released November 9, 2026) and [Open WebUI v0.13.4](https://github.com/open-webui/open-webui/releases/tag/v0.13.4) (released November 17, 2026). The install script and the Compose file are the same. The video was recorded in January 2025, and my speed impressions and the walkthrough come from that recording.

## Which DeepSeek R1 Are We Running?

The full DeepSeek R1 is a 671 billion parameter model. You are not running that on a Pi, or on most desktops for that matter. What DeepSeek also released is a set of **distilled** models: smaller, existing open models fine-tuned on reasoning data generated by R1. They "think" the same way, showing their reasoning before giving the answer, but they fit on normal hardware.

The [`deepseek-r1` page in the Ollama library](https://ollama.com/library/deepseek-r1) lists these smaller tags right now:

| Tag | Based on | Download size |
|---|---|---|
| `deepseek-r1:1.5b` | DeepSeek-R1-Distill-Qwen-1.5B | 1.1GB |
| `deepseek-r1:7b` | DeepSeek-R1-Distill-Qwen-7B | 4.7GB |
| `deepseek-r1:8b` (also `latest`) | DeepSeek-R1-0528-Qwen3-8B | 5.2GB |
| `deepseek-r1:14b` | DeepSeek-R1-Distill-Qwen-14B | 9.0GB |

Bigger tags go all the way up to the 404GB full model. On a Pi, the 1.5B model is the one to use. I did try the 7B on the Pi, and I really wouldn't recommend it.

![The deepseek-r1 page in the Ollama library with the 1.5b tag selected, showing its 1.1GB size and the ollama run command, as it looked in the video](/docs-static/img/2026/10/deepseek-raspberry-pi-ollama-open-webui/ollama-library-1-5b.jpg)

One change since the video: back then, the default `deepseek-r1` tag was the 7B model. Today, a plain `ollama run deepseek-r1` pulls the 8B model built on the R1-0528 update. That's why every command in this guide spells out the `:1.5b` tag. If you run the plain tag on a Pi, you'll be downloading a model that's far too big for it.

According to the Ollama library page, the model weights are MIT licensed. The Qwen-based distills come from Qwen 2.5 models, which were originally released under Apache 2.0.

DeepSeek R1 isn't the newest small model on the block anymore, and that's fine. Everything below works the same way for any other small model in the [Ollama library](https://ollama.com/library). Just swap the model name.

## What You Need

- **A Raspberry Pi 5 running a 64-bit Debian or Ubuntu based OS.** My Pi runs the latest Ubuntu Server, which is my personal favorite on it, but Raspberry Pi OS is fine too. Flashing any of these to an SD card is easy with [Raspberry Pi Imager](https://www.raspberrypi.com/software/). It has to be a 64-bit install: the Ollama installer only accepts `x86_64` and `aarch64`/`arm64` and stops on anything else.
- **Some free storage.** Ollama's arm64 download alone is roughly 1.5GB right now, plus 1.1GB for the model, plus the Open WebUI container image.
- **Docker with the Compose plugin** for the Open WebUI half of the guide. More on that below.

You can do all of this over SSH, so the Pi doesn't need a monitor or keyboard.

## Install Ollama

First things first, update the system:

```bash
sudo apt update && sudo apt upgrade -y
```

Ollama's installer gets piped from `curl`, so you need that. Current Ollama releases also ship as `.tar.zst` archives, and the script stops with an error if `zstd` isn't installed. The video didn't need this step, but install both now to save yourself a failed run:

```bash
sudo apt install -y curl zstd
```

Then run the official install script:

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

If you don't like piping scripts into a shell, totally fair. Download it first and read it. On a Pi, this is what it does:

- Detects `aarch64` and downloads `ollama-linux-arm64.tar.zst` from Ollama's releases, then extracts it under `/usr/local` (the binary goes in `/usr/local/bin`, the libraries in `/usr/local/lib/ollama`).
- Creates an `ollama` system user with its home at `/usr/share/ollama`, adds it to the `render` and `video` groups, and adds your user to the `ollama` group.
- Writes `/etc/systemd/system/ollama.service`, then enables and starts it.
- Checks for NVIDIA or AMD GPUs. There aren't any on a Pi, so it skips the driver steps.

At the end, you'll get a warning that no NVIDIA/AMD GPU was detected and Ollama will run in CPU-only mode. That's fine and expected. If `lspci` and `lshw` aren't installed, the warning instead says it can't detect a GPU at all. Same result. Running on the CPU alone is the main reason we're sticking with the smallest model.

Check that the service is up:

```bash
ollama -v
systemctl status ollama
```

The installer also tells you the API is now listening on `127.0.0.1:11434`. Remember that address, because it matters when we get to Docker.

## Run DeepSeek R1 in the Terminal

Running the model is a single command. You can grab it from the model's page on the Ollama site:

```bash
ollama run deepseek-r1:1.5b
```

The first time, Ollama downloads the model. At 1.1GB it doesn't take long. After that you land right in a chat prompt, and just like that, you're talking to DeepSeek on a Raspberry Pi.

I started with a simple "hello", and it thought about it for a bit and gave me a pretty generic response. Then I asked something a little more involved: why should I use a GPU with R1? It did exactly what you'd expect from a reasoning model and walked through its whole thought process before answering.

![DeepSeek R1 1.5B in the terminal on the Pi, answering a quick hello and then starting its think-tag reasoning on a question about GPUs](/docs-static/img/2026/10/deepseek-raspberry-pi-ollama-open-webui/terminal-chat.jpg)

While that was running, I opened a second terminal on the Pi to check the resources, and it was cooking. Every last bit of CPU it had went into that response. Still, it did pretty well. The first tokens take a bit, and then it writes faster than I can read along.

![htop on the Raspberry Pi 5 showing all four CPU cores near 100% while the ollama runner generates a response](/docs-static/img/2026/10/deepseek-raspberry-pi-ollama-open-webui/htop-cpu.jpg)

If you want real numbers on your own hardware, add `--verbose` and Ollama prints timing stats after every response:

```bash
ollama run deepseek-r1:1.5b --verbose
```

Type `/bye` (or press Ctrl+D) to leave the chat. A few other commands you'll want:

```bash
ollama list                    # models you've downloaded
ollama ps                      # models currently loaded in memory
ollama rm deepseek-r1:1.5b     # delete a model and free the space
```

Models live in `/usr/share/ollama/.ollama/models` when Ollama is installed as a service.

## Add Open WebUI

Chances are you don't want to spend most of your time in the terminal chatting with this thing. [Open WebUI](https://docs.openwebui.com) gives you a web interface that looks a lot like the DeepSeek or ChatGPT web apps, plus extra features like uploading a PDF and asking questions about it. We're running it in Docker, and Open WebUI's official image is built for both amd64 and arm64, so the Pi is fine.

### Install Docker

If Docker isn't on the Pi yet, follow Docker's official instructions for [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) or, on 64-bit Raspberry Pi OS, [Debian](https://docs.docker.com/engine/install/debian/). Then do the [post-install steps](https://docs.docker.com/engine/install/linux-postinstall/) if you want to run `docker` without `sudo`. And if Docker is new to you entirely, my [Docker basics for beginners](/7-docker-basics-for-beginners) guide covers everything you need to get started.

### Let the Container Reach Ollama

Out of the box, Ollama only listens on `127.0.0.1`. That's localhost on the Pi itself, and from inside a Docker container, that's not the Pi. The container can't see it, so Open WebUI would come up with no models at all.

The installer set Ollama up as a systemd service, so we'll add an override to it:

```bash
sudo systemctl edit ollama.service
```

An editor opens. Put this between the comment lines near the top, where it tells you anything in that space becomes the override:

```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
```

Save and exit, then reload systemd and restart Ollama:

```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

Do note what `0.0.0.0` means: Ollama now listens on **every** network interface, localhost included. That's what lets the Docker container through. It also means anything else on your network can reach it.

<Warning>
Ollama's API on port `11434` has no authentication. With `OLLAMA_HOST=0.0.0.0`, anyone who can reach the Pi can run prompts, pull models onto your storage, or delete the ones you have. On a trusted home LAN that's a trade-off you can make, but never port-forward `11434` or expose it to the internet. If you'd rather keep Ollama on localhost, use the host-networking setup further down instead.
</Warning>

### The Compose File

You can put this wherever you like. I keep my containers in my home directory, so I'll make a folder for it there:

```bash
mkdir ~/openwebui
cd ~/openwebui
```

Open WebUI wants a secret key so your logins survive container updates. Generate one into a `.env` file next to the compose file, and Compose will pick it up on its own:

```bash
echo "WEBUI_SECRET_KEY=$(openssl rand -hex 32)" > .env
chmod 600 .env
```

Now create the compose file:

```bash
nano compose.yaml
```

```yaml
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    container_name: open-webui
    volumes:
      - ./data:/app/backend/data
    ports:
      - 3000:8080
    environment:
      - OLLAMA_BASE_URL=http://host.docker.internal:11434
      - WEBUI_SECRET_KEY=${WEBUI_SECRET_KEY}
    extra_hosts:
      - host.docker.internal:host-gateway
    restart: unless-stopped
```

Walking through this real quick:

- **`image`** pulls Open WebUI from GitHub's container registry. The `:main` tag is the one the docs recommend. If you'd rather pin a release, versioned tags like `:v0.13.4` exist too.
- **`volumes`** creates a `data` folder right next to the compose file (`./` just means the current directory) and maps it to where Open WebUI stores its database, chats, users, and uploads. This is the folder to back up.
- **`ports`** is `host:container`. The `3000` on the left is the port you'll use in the browser, and you can change it. Leave the `8080` on the right alone, since that's what the app listens on inside the container.
- **`extra_hosts`** makes `host.docker.internal` resolve to the Pi itself, and **`OLLAMA_BASE_URL`** tells Open WebUI to find Ollama there. Two lines this compose file has that mine in the video didn't: `OLLAMA_BASE_URL` (Open WebUI's image already falls back to this exact URL, I'm just making it explicit) and `WEBUI_SECRET_KEY`, which the current docs ask for.
- **`restart: unless-stopped`** brings it back after a reboot unless you stopped it yourself.

Save and exit (Ctrl+X in nano), then launch it:

```bash
docker compose up -d
```

The `-d` means detached, so it runs in the background. Compose creates a network for the stack and then the `open-webui` container. The first start can take a little while, so follow the logs and wait for `Application startup complete`:

```bash
docker compose logs -f
```

### The Tighter Option: Keep Ollama on Localhost

If the open port in that warning bothers you, here's another way to do it. Open WebUI's own troubleshooting docs suggest running the container on the host's network. That way it reaches Ollama on `127.0.0.1` directly, and Ollama never has to listen on your LAN.

To set it up, undo the override from earlier. This removes the drop-in entirely, so only use it if `OLLAMA_HOST` was the only thing you added:

```bash
sudo systemctl revert ollama.service
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

Then use this compose file instead:

```yaml
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    container_name: open-webui
    network_mode: host
    volumes:
      - ./data:/app/backend/data
    environment:
      - PORT=3000
      - OLLAMA_BASE_URL=http://127.0.0.1:11434
      - WEBUI_SECRET_KEY=${WEBUI_SECRET_KEY}
    restart: unless-stopped
```

With host networking, Docker ignores `ports` mappings, so `PORT=3000` tells Open WebUI to listen on port 3000 directly. Same URL, but now only Open WebUI and its login screen are on the network.

## First Login

In a browser on any machine on your network, go to the Pi's IP address on port 3000, something like `http://192.168.1.50:3000`. Click **Get started**, then fill in a name, email, and password to create your account.

All of this stays local in that `data` folder, so the email doesn't have to be real. But do note that the **first account you create becomes the administrator** for the whole instance. Create it right away, before anyone else on the network finds the page, and use a real password. Once the admin exists, new sign-ups are switched off. If you want family members on it, turn **New Sign Ups** back on under **Settings > Admin > Authentication**. Their accounts then wait as pending until you approve them.

It also shows you a "what's new" screen. I'd read it. There's a lot this tool can do beyond the chat box.

## Using It on the Pi

Your models are in the selector at the top left. Pick `deepseek-r1:1.5b` and chat with it exactly like you did in the terminal.

To give it a real workout, I used one of the suggested prompts: a code snippet for a sticky website header in both CSS and JavaScript. With a second terminal open, you could see the Pi was definitely working. The reasoning shows up in a collapsible section above the answer. You can expand it to watch the model think, or hide it if you just want the result.

![Open WebUI with deepseek-r1:1.5b selected and the expanded Thought for a few seconds section showing the model's reasoning about a sticky header](/docs-static/img/2026/10/deepseek-raspberry-pi-ollama-open-webui/open-webui-thinking.jpg)

It was not fast, though. For a comparison, I pasted the same prompt into the 7B model running locally on my M4 Mac Mini. That's a better model on much better hardware, and it finished in about 45 seconds. The Pi with the 1.5B model took something like three or four minutes. The 7B and 8B models both run perfectly well on that Mac Mini, and they generally give better results, they just need hardware the Pi doesn't have.

Then I cleared the chat and tried the PDF upload I mentioned earlier. I grabbed the only PDF I had on that system, which happened to be a payment document, and asked it to summarize it. It took about three minutes, but it worked well. It correctly pulled out that the document described a payment from one company to another for a product, along with the total price. (I had to blur all of that in the video, for obvious reasons.)

![A PDF attached in Open WebUI with a prompt asking deepseek-r1:1.5b to summarize the invoice](/docs-static/img/2026/10/deepseek-raspberry-pi-ollama-open-webui/open-webui-pdf-upload.jpg)

You don't have to go back to the terminal to try other models, either. As the admin, type a model name into the model selector in a new chat and Open WebUI will offer to pull it from Ollama. Keep it to the small ones on a Pi.

## A Note on Ollama's Cloud Features

Ollama has added optional cloud-hosted models since this video, and those send your prompts to Ollama's servers. Running local models like we've done here doesn't. If the whole point of this for you is keeping everything on your own hardware, like it was for me, Ollama's [FAQ](https://docs.ollama.com/faq) documents a local-only mode. Add it to the same systemd override:

```bash
sudo systemctl edit ollama.service
```

```ini
[Service]
Environment="OLLAMA_NO_CLOUD=1"
```

Restart Ollama afterward (`sudo systemctl restart ollama`). If you went with the `0.0.0.0` setup, keep your `OLLAMA_HOST` line in there too, since both go under the same `[Service]` section.

## Updating and Removing

To update Ollama, re-run the install script. It replaces the old version in place:

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

To update a model to the latest version of its tag:

```bash
ollama pull deepseek-r1:1.5b
```

To update Open WebUI, back up the `data` folder, then from `~/openwebui`:

```bash
docker compose pull
docker compose up -d
```

To get rid of Open WebUI, run `docker compose down` in that folder and delete the folder. Ollama's [Linux docs](https://docs.ollama.com/linux) have the full uninstall steps for the service, binary, models, and `ollama` user. Since the script installed under `/usr/local`, the `which ollama` based commands there will find the right paths.
